# K6 후속 수읽기 확인 — 순차 연구 1단계

1단계는 K6의 평가 변화 원인 확인이다. 기존 앱·모델·규칙·운영 소스를 변경하지 않고 실제 기보와 유한 비교로 조사했다. 원인은 **같은 국면에서도 얕은 지평이 상대의 연결 공격을 좁게 읽는 복합 제한**으로 확인됐다. 45수의 L9→N4 변경은 완료된 비교 뒤 검증된 반증을 반영한 결과다. 최초 패착·이기는 대안·기력 개선은 아직 확인한 결과가 아니다.

사용자가 지시한 순서는 ① K6 후속 수읽기 확인 → ② K5 공격 지속 보완 → ③ CPU 배분 검증이다. 1단계 완료 검증 전에는 2·3단계를 실행하지 않는다. 새 소스 후보는 전체 최대 2개이며, 기존 22승 보존과 I4·K6 승리 전환을 같은 후보의 실제 24판에서 확인하기 전에는 기존 앱을 변경하지 않는다.

## 입력과 보존

- 비교 기준: 미채택 v5.18.17, 소스 `afbd6df26b37e256e825ed5c156c6ea1f362f851b101c3e5dfc2c6adcc89098b`.
- 동결 HTML: `16de6320d8d57937f4aee184b4253101b2f92d57abb987fcff0a5b495767365f`.
- 같은 8119 모델, 전체 SHA-256 `fce1c849e6eb05a1ec839550a2dc29ca509b0c7ce0d7ea6150095eeee1a91932`.
- 기존 앱 v5.18.10의 SHA-256 `c89d82c623c8e7dd15b139d9379ce43fd84ab2d0c27093a445ba904c26ad6bf0`와 167개 소스·검사·빌드 바인딩을 확인했다.
- 실제 K6 기보 98,545,563바이트의 SHA-256은 `22fd9ae39c80b4feeb814d3d6b5400360ccf12171198609ebc265f181c083411`이다. 41~49수의 작은 요약만 추출하고 원본은 유지했다.

실제 착수·해시 연결·PV 합법성을 별도 규칙으로 확인했다. 43수 N6 뒤 44수 L8은 상대 자신의 즉시 승리가 없는 상태의 유일한 합법적 즉시 차단이었다.

## 같은 깊이로 맞춘 결과

43수의 완료 깊이는 7, 실제 45수의 완료 깊이는 9다. 앞선 두 수를 적용하면 부모 탐색에 대응하는 남은 깊이는 5다. 따라서 7과 9의 점수를 그대로 대조해 오류라고 판단하지 않았다.

| 비교 | 원탐색 값 |
| --- | ---: |
| 43수 N6, 깊이 7의 후보 원점수 | +503.246191 |
| 같은 생성 보드에서 N6·L8 적용 뒤 깊이 5, ply 2 | +503.246191 |
| 실제 45수 보드로 새로 생성한 뒤 깊이 5, ply 2 | +503.246191 |

기존의 잎별 5ms VCF 제한을 둔 복사본과, 전체 호출 제한 안에서 해당 VCF 소검사를 끝내는 비교 복사본 모두 이 값과 PV를 재현했다. 후자는 원래 시간 배분과 다른 진단 대조군이며 네이티브 실행 자체로 표시하지 않는다. 새 Reader에서 후보 순서 교환·TT 비활성화도 깊이 5의 L9·N4 원점수와 일치했다. 이 재현은 캐시 오염이나 새 국면 생성의 점수 전달 오류를 지지하지 않는다.

43수의 정책 보정은 +71.36, 45수 N4는 +69.60이며 압박 보너스와 템포 감점은 모두 0이다. 보정 차이는 −1.76점으로, 전체 약 −896.59점 변화의 대부분은 원탐색의 깊이 차이다. 이를 가산점 조정으로 해결할 근거는 없다.

## 같은 판에서 갈린 상대 연결 공격

부모 예상의 `N6→L8→L9→M10→N4→M3→L10`과 실제 두 수 뒤 예상의 `N4→M3→L9→M10→L10`은 같은 판에 도달한다. 그 판은 흰돌 차례이며 다음 두 탐색이 달랐다.

| 조건 | 읽은 범위·예상 | 백 관점 원점수 |
| --- | --- | ---: |
| 부모의 남은 깊이 0 | 지평 확장 후보 N9·M5, N9 선택 | −503.246191 |
| 후속 분석의 남은 깊이 4 | 일반 후보에 J3 포함, J3 선택 | +391.585418 |

얕은 선택 전의 후보에는 실제 사목 N9·I4·J3가 있었지만 대표 공격 하나와 차단/연결 절단 하나를 택하면서 N9·M5만 남았다. 더 깊은 탐색은 `J3→I4→N3→O2→N9→O10→O3`를 읽었다. 그중 N3는 즉시 5목 완성점이 생기는 사목이 아닌 준비 수이며, 얕은 준비 후보에는 포함되지 않았다.

**J3 하나의 누락만 원인이라고 결론 내리지 않았다.** 같은 얕은 지평에서 J3를 강제로 읽으면 백 관점 값은 −830.110205로 더 나빴다. 실제 사목을 일반적으로 최대 4개 보존하고 기존 조용한 후보를 남기는 비공개 대조군도 이 잎의 값을 바꾸지 못했다. 그 대조군의 부모 전체 깊이 7 호출은 4초 안에 완료되지 않았으므로 개선 근거로 사용하지 않는다.

준비 수와 필수 차단을 거치는 뒤쪽 제한도 별도로 확인했다. 깊은 PV의 합법적 분기를 O10까지 적용한 동일 보드에서, 원래 지평을 계산하면 추가 수 예산은 0이고 준비 허용량도 소진된다. 이 계산에서 N3는 백 준비 허용량을, O2는 흑 준비 허용량을 소비한다. 더 깊은 일반 탐색에서는 이 두 수에 지평 확장의 준비 허용량을 쓰지 않는다. 이 분기는 얕은 선택이 실제 방문했다는 뜻이 아니라, 후속 제한을 분리한 합법적 반사실 비교다.

| 동일 보드의 제한 대조 | 백 관점 원점수 | 후속 O3 탐색 |
| --- | ---: | --- |
| 원래 계산된 제한 | −864.477385 | 없음·정적 종료 |
| 추가 수 예산만 복원 | −864.477385 | 없음 |
| 준비 허용량만 복원 | −864.477385 | 없음 |
| 두 허용량을 함께 복원 | +391.585418 | O3→H4→G4→F6→E5 |
| 깊은 분석에 대응하는 제한 | +391.585418 | 같은 PV |

따라서 후보 폭 하나나 캐시만 고치는 수정으로 충분하다는 가설은 기각한다. **공격 후보 보존, 준비 공격 허용량, 필수 응수까지 소비하는 추가 수 한도가 겹치는 경계**가 다음 보완의 대상이다. 이 진단용 한도 복원을 운영 코드에 적용하거나 성능·승리를 검증한 것으로 표시하지 않는다.

## L9 제외와 최종 N4의 의미

45수의 완료 깊이 9 비교는 L9를 −146.946790, N4를 −321.985418로 평가해 처음에는 L9를 더 높게 골랐다. 이후 L9 뒤 상대의 준비 공격을 포함한 반증이 발견돼 제외됐다. 그래서 최종 추천은 남아 있는 완료 비교의 N4가 됐다. 시간이 끝나는 순간 작업 중이던 N4가 무심코 반환됐다는 설명과 다르다.

기존 반증은 44,783,035바이트이며 전체 SHA-256 `68b46cd99335b49ad940d33670fc61b79dea995de78e0b512054b382e1ad9747`이다. 정확히 45수 전 보드에 흑 L9를 놓은 상태에서 백 공격 증명을 기존의 별도 규칙 검사기로 검증했다. **1,011,604개 논리 노드, 1,009,132개 합법 방어 응수, 1,002,867개 VCF 잎**을 통과했고 보드도 복원됐다. 새 승리 탐색을 실행한 것이 아니라 저장된 증명을 재생한 결과다.

`forcingChecksComplete:false`는 병렬 초기 700ms 계획에서 이어지는 값이므로 그 플래그만으로 최종 후보 검사의 상태를 알 수 없다. 실제 43수 N6와 45수 N4의 별도 최종 검사도 각각 미완료·미반증이었고, 안전 증거로 세지 않는다. L9의 검증된 반증과 남은 N4의 미검증 상태를 구분한다. N4의 안전이나 더 앞선 국면의 회피 가능성을 증명하지 않았다.

## 실행 범위와 후속 단계

유한 엔진 비교는 총 30회 중 28회 완료, 2회 미완료이며, CPU 계정은 18.033초/90초다. 부분 결과를 전체 완료 비교로 사용하지 않았다. 입력 준비 CPU 1.968초와 저장 증명 검증을 포함한 별도 준비 CPU 23.718초는 엔진 탐색 계정과 분리했다. 처음의 후속 진단 도우미는 세 호출 뒤 소스 관찰 지점의 교체 단언에서 실패했다. 해당 코드·실패·세 유효 호출을 보존했고, 실행되지 않았던 대조군은 새 도우미로만 진행했다. 앞선 두 실행에 사용한 진단 코드도 실행 당시 해시와 일치하는 바이트를 별도 보존했다.

이 단계의 완료는 원인 진단과 증거 확인이다. 소스·앱·모델·규칙은 그대로이고, 새 네이티브 분석이나 전체 대국은 실행하지 않았다. K6가 선공 승리로 바뀌었다거나 최초 패착을 찾았다고 주장하지 않는다.

로컬 근거는 `work/k4-three-stages-20261028/stage1/`의 `baseline.json`, `inputs.json`, `refutation-audit.json`, 각 `*-result.json`, `harness-versions.json`, `completion.json`에 연결한다. 1단계 완료 명세를 실제 검증한 뒤 **2단계 K5 공격 지속 조사**를 시작하고, 3단계 CPU 비교는 그 뒤에 진행한다. 기존 결과·후보·실패 원본은 덮어쓰지 않는다.
