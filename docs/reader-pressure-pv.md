# 완료 PV에 따른 압박 보너스 확인

v5.18.15는 **로컬 실험 후보이며 공개 엔진과 사용자 앱에 적용하지 않았다**. 필수 대국의 개선·보존 조건을 충족하지 못해 미채택으로 남긴다. 아래는 이 실험 후보가 기존의 제한 전략 probe의 압박 보너스를 완료된 Reader 수순과 대조한 구현·검사 기록이며, 공개 저장소의 현재 기능을 설명하는 문서가 아니다.

실험 구현은 원탐색 점수·다른 보정·템포 페널티를 유지하고, 한 수순의 공격 지속 근거와 강제승·안전 증명을 구분한다. `analyze` 호출 형식도 유지했다.

이 변경을 조사한 실제 대국과 실패 결과는 [K4 개장 연구](k4-opening-study-20261026.md)에 별도로 남긴다. 기능 검사 통과를 새 대국 승리나 채택으로 해석하지 않는다.

## 기존 주장과 실제 지원 근거

기존 `strategy.probe`는 일부 후보와 제한된 상대 응수를 비교한다. 완료한 표본 응수에서 공격이 이어졌을 때 기존 압박 단위 420을 주장할 수 있지만, 이는 모든 합법 응수의 증명이 아니다.

Reader의 두 경로가 공통 `pressureForPV`를 사용한다.

- 직렬 `analyze`: 해당 깊이에서 완료한 후보의 원탐색 점수와 PV에 적용한다.
- Worker용 `compareRoots`: 전달된 `rootPolicy.pressure`를 미리 검증된 보너스로 취급하지 않고 같은 확인을 수행한다.

보너스의 원래 주장은 `pressureClaim`, 실제 적용값은 `pressureBonus`로 구분한다. `pressureClaimEvidence`와 `selectedCheck`에는 기존 probe의 표본 범위를 보존하고, `pressureEvidence`와 `selectedPressureSupport`에는 실제 완료 PV의 확인 결과를 남긴다. 서로 다른 두 근거를 합쳐 더 넓은 응수 범위를 검사했다고 표시하지 않는다.

원래 압박 주장이 없으면 새 보너스를 만들지 않는다. 기존 전술 점수 범위에 속하는 결과도 이 보정의 대상으로 바꾸지 않는다. 위치 평가인 경우에만 PV 첫 수와 실제 후보 좌표가 같은지 확인하고, `supported`일 때 기존 압박 주장만 적용한다.

## 최대 5수의 실제 재생

`pressurePVSupport`는 현재 Reader 보드에서 다음 순서의 최대 5수를 실제 합법성 판정과 `set`으로 재생한다. 별도의 후보 탐색을 추가하거나 임의의 가상 자기 차례를 만들지 않는다.

1. 자기 후보를 둔다. 실제 정확한 5목이면 우선 처리한다. 종료 뒤 PV가 더 이어지면 잘못된 수순이다.
2. 자기 후보가 상대에게 즉시 정확한 5목을 허용했으면 압박을 지지하지 않는다. PV의 상대 수가 그 승리를 놓치더라도 이 경계를 우회하지 못한다.
3. PV의 상대 응수와 자기 후속 수를 둔다. 자기의 실제 5목은 우선한다. 그 외에는 상대 즉시승리가 없고 자기의 합법적인 정확한 5목 끝점이 있어야 한다.
4. 끝점이 하나이고 상대가 합법적으로 막을 수 있으면, PV가 실제로 그 필수 방어를 둬야 한다. 다른 응수나 누락으로 확인을 대신하지 않는다.
5. 실제 방어 뒤 자기의 다음 수를 두고 정확한 5목 또는 새 4목 위협이 이어지는지 확인한다. 필수 방어 뒤 조용한 진형 확장으로 공격이 끊기면 보너스를 지지하지 않는다.

여러 승리 끝점이나 금수 때문에 막을 수 없는 유일 끝점처럼 더 짧은 확인으로 조건이 충족되는 경우도 있다. `checkedPlies`는 실제로 재생한 길이를 기록한다. 이 도우미는 긴 PV 전체를 검사하는 도구가 아니며, 전체 PV의 합법성 검증은 별도 계약이다.

| 상태 | 의미 | 압박 보너스 |
| --- | --- | --- |
| `supported` | 확인한 한 완료 PV에서 압박 조건이 이어짐 | 기존 주장 적용 |
| `contradicted` | 확인한 수순에서 즉시 반격 또는 공격 단절을 확인함 | 0 |
| `unknown` | 짧은 PV·다른 필수 방어 등으로 조건을 확인하지 못함 | 0 |
| `invalid` | 후보 불일치·점유점·금수·종료 후 착수 등 잘못된 수순 | 0 |
| `not-applied` | 기존 전술 점수 범위여서 보정 확인 대상이 아님 | 0 |

모든 지원 근거는 `proven:false`, `replyCoverage:'one-completed-PV'`다. `supported`는 승리나 안전의 인증서가 아니고, `contradicted`도 해당 후보의 강제패배 증명이 아니다. 일반 탐색의 공격권 표시는 선택한 PV가 지지하지 않으면 `unknown`으로 낮추지만, 즉시 승리·기존 강제승 증명 경로를 이 보정으로 대신하지 않는다.

## 시간 종료와 완료 라운드

합법성·정확한 5목·승리 끝점 검사 전후에 기존 Reader 기한을 확인한다. 재생 중 놓은 돌은 결과나 예외와 관계없이 `finally`에서 역순으로 `set(i,0)` 한다. 원래 창별 돌 수·평가 기여·4목 집합·근방 계수와 신경망 재사용이 원래 국면으로 돌아와야 한다.

도우미를 직접 호출했을 때 시간 종료는 `unknown`, 사유 `deadline`이다. 그러나 `pressureForPV`는 이 사유만 다시 `timeout`으로 전파한다. 시간 부족을 보너스 0인 완료 후보로 바꾸면 라운드의 마지막 후보만 미검증이어도 새 라운드가 채택될 수 있기 때문이다.

- `analyze`는 미완료 라운드를 버리고 직전 전체 완료 라운드를 유지한다.
- `compareRoots`는 그 후보 행을 추가하지 않고 부분 결과와 `complete:false`를 반환한다.
- 짧은 PV로 인한 `unknown`은 시간 종료와 구분한다. 원탐색 비교가 완료됐다면 보너스 0인 정상 결과로 남을 수 있다.

## 생성 검사와 fixture 교정

로컬 실험 후보에만 있는 새 `test/reader-pressure-pv.cjs`는 공개 API를 늘리지 않고 검사 전용 VM에서 실제 내부 도우미를 노출한다. 실제 규칙 판정기를 이용해 열린 3목과 막힌 3목에서 시작하는 5수 압박을 두 색·D4로 검사한다. 양성 32건과 반복 반례 256건 외에 금수·장목·즉시승리 우선·상대 즉시승리·전술 점수 제외·마지막 callback의 기한을 검사한다. 작은 생성 신경망과 모델 없는 경우 모두 중단 뒤 보드·창·근방 계수 복원, 동일 Reader 재사용과 새 Reader 점수 일치를 확인한다. 제어된 자식 점수와 실제 규칙 재생을 사용한 호출 통합 검사는 마지막 후보의 시간 종료가 완료 행·새 라운드로 발행되지 않는지도 확인한다. 이 새 검사를 공개 저장소의 현행 검사로 표시하지 않는다.

로컬 실험 분기의 기존 `test/reader-pressure.cjs` 경쟁점 G7은 실제 5수 양성 PV를 만들기 위해 H9·H7 돌을 추가한 뒤 변경된 fixture의 후보군에서 빠졌다. 이를 엔진의 후보 정책으로 되돌리지 않았다. F9로 경쟁점을 고치되 합법성·즉시승리 아님·4목 없음·`forcing:false`와 실제 후보군 포함을 단언했다. 기존 420 대 100 순위, 템포 420, 불완전 probe·전술 점수·필수 수 우선 단언은 유지했다.

실패한 실제 focused 실행의 오류·debug 기록은 로컬 `retention-phase/reader-pressure-fixture-failure.log`에, 교정 후 통과 출력은 `reader-pressure-v15-focused.log`에 보존했다. 실패를 지우거나 통과 기록으로 덮지 않았다. 실험 검사는 이 로컬 기록에 의존하지 않는 작은 생성 fixture이며, 공개 CI에 반영된 변경이라는 뜻은 아니다.
