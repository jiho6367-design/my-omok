# K5 후속 수읽기의 계산 비용 보완

앞선 두 후보는 준비·역공 후보 누락을 보완했지만, 기존 34돌 기보의 1.5초 검사에서 첫 후보 비교를 끝내지 못했다. [이전 조사](k5-followup-stage2-20261028.md)의 실패 기록·168개 소스/검사·원본을 미채택 상태로 보존했고, 사용자가 추가 후보 최대 2개를 명시적으로 허용했다. 총 한도는 4개이며 이 문서의 v5.18.20은 세 번째 후보다. 순차 3단계의 기능 검사·CPU 배분·대국 합격 조건은 유지한다.

## 원인과 선택한 구현

같은 기보 검사 흐름의 대조에서 기준 v17은 약 1,197ms에 24개 후보를 모두 비교했지만 후보2는 17개만 끝냈다. 사전 검사는 양쪽 약 675ms로 비슷했다. 추가된 후속 수읽기의 본 탐색 비용이 커진 근거이며, 전체 기력이나 브라우저 처리량의 배속비를 뜻하지 않는다.

세 번째 후보는 탐색 폭·깊이·준비 허용량·시간 배분을 유지하고 세 가지 계산 경로를 보완했다.

- 같은 보드와 차례에서 이미 완료한 준비 후보의 **좌표 목록만** Reader 안에 최대 2,048개 보관한다. 빈 목록도 구분하고, 재사용할 때 새 배열·객체를 만든다. 자격 검사와 기존 시간 검사는 유지하며 시간 초과·평가값·PV·증명은 저장하지 않는다.
- 옵션을 생략한 Reader는 기존의 돌 개수 기반 빠른 국소 계산을 사용한다. 명시적 `optimized:false`는 원래 창을 직접 세는 참조 계산을 유지한다.
- 빠른 계산의 창 자료는 실제로 요청한 칸에서만 준비하고 재사용한다. 규칙 검사만 하는 생성 객체에는 이 자료를 만들지 않는다.

실제 앱은 이미 빠른 계산을 명시하므로 기본값 변경만으로 앱이 빨라졌다고 주장하지 않는다. 후보 생성의 원래 공격·차단·겸용 대표와 Q6·루트 24개·마스크 15, 필수 차단·승리 증명·캐시 `node-v12`의 완료 값 의미는 유지했다.

## 실제 대조 범위

문제 기보의 같은 8개 후보를 고정해 모델 없음/참조 계산과 기존 8119 모델/빠른 계산을 따로 비교했다. 네 쌍·8호출 모두 완료 점수와 PV가 같았다. 처음 비교의 준비 후보 재계산은 190→149회와 189→149회였고, 같은 완료 루트를 다시 요청한 대조에서는 8→0회였다. 재요청 대조를 첫 검색의 처리량으로 확대하지 않는다.

원래 Reader 기보 검사 전체도 수정 전과 비공개 결합 대조군으로 각각 한 번 실행했다. 수정 전 후보2는 종료 코드 1, 결합 대조군은 원래 60개 시나리오를 종료 코드 0으로 통과했다. 문제 국면은 각각 18개/24개 후보를 완료했으며, 결합 대조군의 첫 비교 완료 시각은 약 1,442ms였다. 후보 집합·사전 검사의 완료 범위가 달라 고정 후보 집합의 배속비로 해석하지 않는다. 이 검사는 모델을 지정하지 않은 공개 Reader 계약이며 실제 앱의 15초·같은 모델 성능과 구분한다.

해당 대조는 원래 인자·콜백·반환 객체·단언을 유지한 비공개 본문 관찰을 사용했다. 관찰 시간은 포함하며, 새 관찰기는 제어한 Reader를 모듈 캐시에 등록한다. 처음 실행 도구의 상대 경로 오류는 엔진 자식 실행 전에 종료됐고, 원본·오류 로그를 보존한 별도 수정 실행 도구로 실제 두 대조를 한 번씩 실행했다.

## 정확성 검사와 현재 상태

작은 생성 fixture로 15·19줄 판의 독립 국소 점수 9,396개, 창·돌 개수·기여 상태 1,236개, 기본/빠른/참조 계산의 완료 비교 6묶음을 검사했다. 작은 NN은 지원하는 15줄 판에서만 사용했다. 회전·반사·색 교환의 메모 대조 32묶음, 452개 준비/필수 차단 간선, 배열 복사·FIFO·빈 목록·자격 제한, 9개 시간 종료 및 복원 검사도 통과했다.

운영 소스에 같은 구현을 반영한 뒤 관련 집중 검사 7개가 모두 실제 종료 코드 0으로 통과했다. 기존 관찰 계약은 후보 생성 hook이 호출됐는지 대신 실제 선택 간선과 독립 규칙으로 준비권 소비를 검사하도록 보완했다. 기존 540개 간선·금수·증명·캐시·보드 복원 단언은 유지했고, 원래 기보 검사와 통합 검사 단언은 바꾸지 않았다. 새 계산 계약을 추가한 전체 명령 수는 76개이며 이전 75개 순서를 유지한다.

새 공개 빌드와 봉인된 후보2에서 독립적으로 파생한 구현도 K5·K6의 기존 4개 짝·8호출에서 완료 값/PV가 같았다. 이 동등성 비교 CPU 3.594초를 포함한 공통 유한 진단 누계는 **83.578초/90초**다. 원래 기보 검사 전체의 기능 검사 CPU 안에 포함된 대상 분석 CPU는 중복 합산하지 않는다.

전체 실행은 실제 종료 코드 0으로 끝났다. 같은 소스에서 원래 34돌 완료 깊이 단언을 포함한 76개 검사, 네이티브 Edge의 생성 공개 baseline HTML에서 승리 16건·필수 사목 방어 352건, NN 점수 705건·특징 벡터 1,410개·시간 종료 복원 6건을 통과했다. UI baseline 국면 검사는 실제 앱의 모델별 기력 비교와 구분한다. 빌드·동등성·전체 회귀·브라우저·NN의 다섯 자식 실행도 각각 종료 코드 0이며, 보호한 실행 앱과 모델은 바뀌지 않았다.

이번 전체 통합 검사는 원본 인자·결과를 바꾸지 않는 반환 후 관찰기를 명시적으로 사용했다. 필터와 advisory는 해제했고 원래 33돌 기보 단언도 통과했다. 이 통과를 관찰기 없는 재실행이나 과거 F7/H7 진단 부재의 일반적인 해결 증거로 바꾸지 않는다. 과거 실패 네 번은 원본 그대로 남긴다.

2단계의 제작·기능 검사 근거를 확보했으며, 이 문서와 현재 169개 소스/검사의 완료 명세를 확인한 뒤에만 3단계 CPU 비교를 시작한다. 8판/24판 승리, 기존 22승 보존, I4·K6 승리 전환은 아직 확인되지 않았다.
