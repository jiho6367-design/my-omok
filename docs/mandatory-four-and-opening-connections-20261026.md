# 필수 4목 차단과 초반 두 축 연결 — v5.18.5

상대의 다음 정확한 5목을 막는 유일한 합법 수는 빠르게·자동·심층·직접 설정 모두 바로 확정한다. 초반에는 두 개의 독립된 축을 새로 연결하는 응수를 하위 탐색에서 보존한다. 안쪽 진행을 강제하거나 바깥쪽의 유효한 공격을 배제하지 않는다. 규칙, 신경망 입력·가중치와 1초·15초·25초 시간 상한은 유지한다.

## 확인한 원인

### 상대 4목의 필수 방어가 분석 중으로 남는 문제

`E.urgent()`는 이미 내 즉시 정확한 5목, 상대의 다음 정확한 5목과 유일 합법 방어를 구분했다. UI의 일반 분석과 예상 응수 경로는 자동 모드 또는 승패 증명만 조기 확정했고, 심층·직접 설정의 필수 방어는 Worker를 계속 실행했다. serial 결과도 병렬 후보 비교가 끝날 때까지 보류됐다. 통합 엔진의 단계별 심층 경로 역시 필수 방어 결과 뒤 최종 후보 검사를 계속했다.

이제 이 세 경로에서 실제 긴급 결과를 바로 사용한다. Worker 진행·최종 메시지의 필수 방어는 현재 보드에서 다시 검사하고, 확인된 반증이나 기존 전체 패배 증거를 덮지 않는다. 확정 시 serial·pool·타이머를 정리하고 화면에 **분석 완료 · 즉시 차단**을 표시한다. 이는 다음 5목의 차단이며 이후 승리나 안전의 증명은 아니다. 내 즉시 승리가 우선하며, 금수 방어 불가·양끝 패배·장목은 별도로 처리한다.

### `H8 → F10 → G7` 뒤 `E9`와 `H10`

수정 전 공개 HTML과 동일한 기존 모델로 사용자가 지적한 **심층 E9 추천 자체**를 재현했다. serial은 H10을 제안했지만 실제 화면의 병렬 Reader는 완료 깊이 7에서 E9를 선택했다. 깊이 8은 미완료라 이미 제외되고 있었으며, 진행 중 후보가 최종 수를 덮은 사례는 아니었다. H10도 루트 후보에 존재했다.

E9 뒤 실제 빠르게 1초 모드의 상대 응수는 **H7**이었다. H7과 대안 G8은 각각 17·18위로 하위 16후보에서 탈락했다. 두 수는 각기 두 축의 2목을 새로 연결하지만, 기존 전략 힌트는 이미 있는 2목 창만 보아 공격·절단 점수가 0이었다. 심층은 실제 H7 대신 D8 같은 응수를 가정했다. 사용자 K4 삼각형에서도 비슷하게 K5가 하위 후보에서 빠졌다.

## 수정 범위와 한계

초반 12돌 이내에서 깨끗한 정확한 5목 창의 단일 돌들을 두 축 이상 연결하는 수를 별도 `connection` 힌트로 인식한다. 후보 자체와 준비 수·4목 수·정확한 5목 끝점의 합법성을 검사한다. 막힌 축, 공간 부족, 장목과 미래 3·3 금수만으로 가능한 연결에는 점수를 주지 않는다.

일반 폭 12 이상에서는 기존 강제수·공격·절단 할당 뒤 연결 후보를 최대 두 개 보존한다. 기존 후보 전체를 늘리거나 특정 좌표를 강제하지 않는다. 좁은 폭 4·6의 정책과 기존 공격 점수·강제수 임계값은 유지한다. 연결의 연속 자기 착수 예시는 **형태의 잠재력**이며 번갈아 두는 실제 PV나 강제승 증거가 아니다. 안쪽이 막히면 유효한 바깥쪽 장축 진행도 계속 비교한다.

K4 전용 규칙이나 H8 주변만 탐색하는 제한은 없었다. 실제 돌 주변 후보와 보드 경계에서 가능한 정확한 5목 창을 사용한다. 신경망에는 기존 중앙 관련 입력이 있으며 이를 삭제하거나 모델을 바꾸지 않았다. 사용자 확인 수순은 `K4 → J5 → L5 → J3 → L4`다. J3 대신 M6, 이후 M3 응수와 I6·J4·L5 등은 별도 국면으로 구분한다. 사용자의 불확실한 다른 좌표를 임의의 패배 사례로 확정하지 않는다. L4를 K6보다 무조건 우선하지 않으며 안쪽 필승 수를 보장하지 않는다.

내부 후보 의미가 달라져 전략 버전을 `initiative-3`, 탐색 캐시 범위를 `node-v4`로 분리했다. 이전 버전의 캐시를 새 후보 정책의 증거로 재사용하지 않는다.
