# v5.18.38 항성 필수 차단 뒤 후속 보강

v5.18.38은 실제 사용자 항성 기보에서 이미 추천하던 두 필수 차단 뒤에 원증명의 조건부 후속을 연결한다. 15수 추천 좌표를 새로 바꾸는 작업이 아니다. 기존 249개 전략과 1,497개 노드의 값·순서·ID를 보존하고, 정확한 15수 시작점 2개를 추가한 251개 전략을 검증했다.

## 정확한 사용자 기보와 두 시작점

사용자의 선공 돌이 백인 실제 8수에서 출발한다.

```text
1 H8   2 G7   3 F8   4 G8
5 G9   6 F10  7 H10  8 E7
9 I9  10 H7  11 I7  12 F9  13 I6
```

위 기보에서 다음 두 경우를 보강한다.

| 상대 14수 | 내 15수 | 15수의 성격 | 이후 증명 범위 |
| --- | --- | --- | --- |
| D7 | F7 | 흑의 즉시승을 막는 필수 차단 | 흑 16수의 합법 210곳과 모든 필요한 후속 |
| E10 | D11 | 흑의 즉시승을 막는 필수 차단 | 흑 16수의 합법 210곳과 모든 필요한 후속 |

두 15수는 기존 즉시 필수 차단 처리에서도 선택하는 수다. 이번 추가의 목적은 그 수를 둔 뒤 상대가 달리 응수해도 검증한 같은 원전략의 다음 선택수를 이어주는 것이다. 원자료의 다른 선택수가 이긴다는 근거를 대신 쓰지 않고, **15 F7과 15 D11 자체**를 각각 현재 규칙으로 검증했다.

두 증명은 합계 420개의 정확한 16수 응수와 그 뒤의 전체 조건부 전략을 포함한다. 각 원증명의 최대 명시 선택수는 전체 33수이며, 즉시승 처리까지 포함한 보수적 종국 상한은 전체 35수다. 선택한 원 DAG 진행도 실제 사용자 8수에서 시작한 브라우저 검사에서 각각 35수 종국까지 이어 두었다.

반대 방향인 `14 D11 → 15 E10`은 이번에 등록하지 않았다. D11과 E10의 이름이 비슷하거나 돌 두 개의 순서를 바꿀 수 있어 보인다는 이유로 같은 증명으로 처리하지 않는다.

## 전체 증명 감사와 보존

규칙은 `15x15-exact5-both33-v1`이다. 양쪽 돌의 정확한 5목과 33 금수를 적용하고, 정확한 부모 기보·돌 색·고정 추천수·좌표 변환·현재의 모든 합법 상대 방어·강제 위협·VCF 종결 조건을 독립 규칙으로 재생했다. 일반 렌주 원평가를 현재 규칙의 필승으로 옮기지 않았다.

새 두 시작점은 각각 선공 색 2가지와 D4 8변환을 적용한 전체 증명 16건, 합계 **32건을 최종 251개 그래프에서 새로 재생**했다. 기존 249개 전략의 3,984건은 모든 원노드·시작점·ID가 그대로임을 대조한 기존 증거 재사용이다. 따라서 전체 근거는 새 재생 32건과 정확한 기존 증거 재사용 3,984건인 **4,016건**이다. 후보를 생산할 때 먼저 실행한 별도 32건은 원증거 계보로만 보존하고 이 합계에 다시 더하지 않았다.

이 수치는 전체 조건부 증명 재생의 범위다. 선택한 기보 두 줄을 끝까지 둔 검사, 실제 엔진 API 조회, 브라우저 클릭 검사와 각각 구분한다. 제한시간 대국 강도를 비교하거나 새로운 학습 모델을 채택한 결과가 아니다.

## 원분석의 예산과 측정값

두 원분석은 고정 15수를 둔 뒤 같은 Reader API에 흑 방어 측을 넣어 실행한 q2 증명 탐색이며, 원선언 예산은 각각 **25,000ms**다. 과거 기록을 수정하지 않고 그대로 연결했다.

| 원분기 | 원선언 예산 | 원 실제 경과 | 원 호출 노드 | 원대표 PV 길이 |
| --- | ---: | ---: | ---: | ---: |
| 14 D7 → 15 F7 | 25,000ms | 약 513ms | 43,390 | 17수 |
| 14 E10 → 15 D11 | 25,000ms | 약 17,414ms | 1,386,065 | 17수 |

두 분석에서 별도로 계측한 증명 탐색의 최대 방문 깊이는 고정 15수 뒤 진입판에서 추가 19수다. 고정 15수까지 부모판 기준으로 포함하면 20수다. 이는 고정 15수를 포함한 대표 PV 17수와 다른 값이다. 비교 탐색은 호출하지 않았으므로 비교 깊이는 null이고 완료 비교를 주장하지 않는다. 경과가 약 513ms였다고 첫 증명의 예산을 1초나 3초로 바꾸지 않았다.

과거 proof/depth/nodes/score는 현재 조회의 실시간 분석값이 아니다. 등록 전략 조회는 실시간 `depth/nodes/score`를 0, `proof`를 null, `proven`을 false로 두고 원증명 식별자와 조회 커서를 별도로 전달한다. 필요한 즉시 차단은 기존 전술 처리와 구분한다. 원 8개 소스의 보존 바이트가 분석 기준 커밋과 v37 배포 커밋에서 같음도 확인했다.

## 미증명 범위와 용량

별도 추가 분석인 `14 D11 → 15 E10`의 q4·60초 결과와 19 J8의 추가 분석은 완전한 승리 증명을 얻지 못했다. 원분석과 불완전 결과를 보존하며 이번 지원에 넣지 않았다. 미증명은 그 수의 필패라는 뜻이 아니다. 일반 실시간 분석의 모든 첫 증명을 새로 저장하고 유지하는 후보 기능도 이번에 채택하지 않았다.

`13 I6` 전체의 필승, `11 I7` 전체의 필승, `9 I9` 전체의 필승은 계속 미증명이다. 별도 `14 F7 → 15 D7` 전위 후보도 이번 두 시작점에 섞지 않았다. 등록된 정확한 부모판에서의 고정수 증명을 다른 상대 응수 전체의 승리로 넓혀 해석하지 않는다.

기존 원자료 S 61,525개, native C 32,602개와 채택 모델 SHA-256 `fce1c849e6eb05a1ec839550a2dc29ca509b0c7ce0d7ea6150095eeee1a91932`는 그대로다. S/C 행 추가는 0개다. 기존 v37의 다른 16주형 지원과 사용자 항성 전략도 보존한다.

| 항목 | 251개 전략 | 유지한 상한 |
| --- | ---: | ---: |
| 시작점 | 251 | 512 |
| 노드 | 1,711 | 65,536 |
| 상대 응수 edge | 229,971 | 262,144 |
| JSON 파일 | 1,022,838 bytes | 8 MiB |
| 모듈 내부 검증 크기 | 1,025,672 bytes | 8 MiB |
| 원자료 S | 61,525 | 65,536 |
| native C | 32,602 | 32,768 |

조회 입력은 40수 미만, 명시 내 정책은 39수 이하, 상대 40수 뒤 기존 즉시승 처리의 종국은 41수 이하라는 구분도 유지한다. 상한을 올리거나 원증거를 삭제하지 않았다. 등록 자료의 원선언 예산 분포는 3,000ms 128개, 15,000ms 27개, 25,000ms 96개이며 현재 실시간 실행의 예산·횟수가 아니다.

## 통합 실행 검사 범위

실제 251개 자료와 FCE 모델을 사용하는 통합 API 검사 547개 조회를 통과했다. 기존 9 I9·11 I7·13 I6 기본 추천 연결, 양색·D4의 필수 차단 15수 부모판 32개, 원 백 선공판의 상대 16수 420곳을 pin 없는 실제 상태에서 확인했다. 이 중 416개는 과거 전략 조회, 4개는 즉시 필수 차단으로 구분했다. 별도의 알려진 pin 표본 64개와 두 선택 진행, 저장한 기보의 원증명 복원도 확인했다. 모듈의 전체 6,720개 양색·D4 응수 조회와 독립 전체 증명 32건은 별도 검사이며 API 547개에 합산하지 않는다.

분리 개인 빌드를 실제 브라우저에서 실행해 사용자 8수부터 두 분기 모두 35수 종국까지 이어 두었다. 보드 클릭 28회, 목록 클릭 2회, 필수 차단 15수의 반투명 선택·undo 각 2회, 17수의 실제 과거 전략 추천을 둔 뒤 원 15수 증명 연결의 생성·저장·재로드 각 2회를 확인했다. 차단 15수 자체의 결과에 과거 proof나 가짜 pin을 붙이지 않았다. 기보 따라두기 off·자동 모드·수동 저장값 1,000ms·390px 화면에서 확인했고 페이지 오류는 0개였다. 이 두 선택 게임은 420판 전체를 브라우저에서 끝낸 검사가 아니다.

기존 249개 범위의 통합 API 1,869개 조회와 기존 221개 범위의 985개 조회, 각각의 브라우저 회귀도 현재 251개 자료를 탑재한 채 별도로 통과했다. 이전 fixture와 노드·시작점 접두를 그대로 검사하며 실제 엔진과 브라우저는 새 전체 자료를 사용한다.

공개 dist와 실제 사용 경로·저장소 개인 출력의 최종 해시·버전·동일 기보 실행, 게시 전 필수 검사 및 Git 동기화는 별도 출시 기록에 남긴다. 전체 npm 검사나 새로운 15초 대국 강도 비교를 수행했다는 뜻은 아니다.
