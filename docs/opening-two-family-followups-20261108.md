# v5.18.33 · 람월·항성의 중앙 선공 후속 보강

중앙 H8에서 선공으로 시작하고 람월(I8) 또는 항성(I3)을 선택했을 때, 기존 추천21수 이후에 비어 있던 대응을 보강한다. 기보 따라두기 체크 없이 자동 최대15초 모드와 반투명 주형 선택에 적용한다. 수 번호는 양쪽 착수를 합친 전체 수다.

## 실제 연결 범위

각 주형에서 중앙 첫3수부터 기존의 실제 추천을 따라21수까지 연결되는 대표 진행을 하나씩 고정했다. 두 판에서 상대의 합법22수는 각각204개이며 기존 자료·사전분석·즉시 전술 대응으로 조회되지 않았다. 이 **408개 입력 모두에23수 대응**을 새로 분석했다.

| 주형 | 중앙 시작 첫3수 | 새 응수 | 선택한 후속의 종국 |
| --- | --- | ---: | --- |
| 항성 I3 | H8 I9 J8 | 217개 | 전체31·35·35수 |
| 람월 I8 | H8 I9 I6 | 216개 | 전체37·37·31수 |
| 합계 | 대표21수 판2개 | **433개** | 선택6가지 모두 정확한5목으로 종료 |

새 응수는23수408개,25수5개,27수6개,29수4개,31수4개,33수4개,35수2개다. 종국 직전의 즉시 승리 수는 기존 전술 엔진이 처리하므로 중복된 사전분석으로 저장하지 않는다. 대국이 끝난 뒤 수순을 늘리지 않았다.

각 주형의 후속3가지는 엔진이 고른 저항 수, 중앙 근처, 원거리 응수를 구분해 선택했다. 그 뒤에는 실제 추천과 상대 응수를 따라 종국까지 진행했다. 모든 가능한 중앙 진행이나23수 이후의 모든 상대 응수를 저장한 것은 아니다. 자료 밖에서는 일반 분석을 이어간다. 기존 기본3수 정책은 유지하며 사용자가 반투명 돌이나 선택 목록에서 두 주형을 선택할 수 있다.

## 원자료와 직접 분석의 구분

[람월 원저자 설명](https://www.ljrenju.com/croom/i08/i08.htm)·[항성 원저자 설명](https://www.ljrenju.com/croom/i03/i03.htm), [대만 원배포 자료실](https://587.renju.org.tw/program.htm) 및 [RenLib](https://www.renju.se/renlib/) 자료를 다시 조사했다. 기존 원자료에서 람월은 일부35수, 항성은17수까지 있지만, 이는 위 대표 진행의 후속이 모두 있다는 뜻이 아니다.

원배포4종에서 두 대표21수 판과408개 실제22수 판을 회전·반사까지 대조했으나 새로 연결되는 원자료를 확보하지 못했다. 따라서 이번 새 원자료S는0개이며 기존61,441개 원자료를 변경하지 않는다. 새433개는 공개 v5.18.32 커밋 `6425fe13c3e3099423a62e74d8c885c6b7d92ddc`와 기존 채택 모델을 고정한 직접 엔진 분석이다. 영상 목록을 확인한 것을 영상의 수순을 검증한 것으로 세지 않았다. 원본 라이브러리·도표·긴 주석·영상은 배포하지 않는다.

입력당3초 분석과750ms 상대 반격 검사를 배정했다. 완료된 후보 비교 또는 검증된 승리 수만 등록하며, 실제 판·차례·선택수·원시 결과와 소스·모델 해시를 보존한다. 이번433개 선택수는 모두 전 합법 방어를 포함한 승리 증명을 별도 규칙·DAG 검증기로 재생했다. 그중25수1개는 원시 출력의 예시·캐시형 증명으로는 독립 재생이 되지 않아 원본을 그대로 보존하고, 동일 판·차례·선택수에5초 상한의 별도 인증을 추가했다. 실제 추가 인증 시간은 약14ms였다. 원래3초 분석의 예산·결과·깊이·노드 정보를 바꾸지 않는다.

## 실행 동작과 보존

새 응수는 기존 `opening-continuation-data.js`의 별도 확장으로 추가한다. 기존31,779개 항목의 순서·좌표·분석·증거와 앞선4개 확장 메타데이터를 보존해 총32,212개가 된다. 저장 상한32,768개와 수읽기 알고리즘·기본 채택 모델은 바꾸지 않는다. 별도 포월174개, 큰 사각형 환원 후속3,767개와 원자료61,441개도 보존한다. 새 모델 채택 작업이 아니다.

현재 판 전체의 돌 색·위치·차례가 일치해야 조회한다. 과거 사전분석의 증명·점수·깊이를 현재 실시간 분석의 승리 판정으로 넘기지 않는다. 원자료와 즉시 승리·필수 방어의 우선순위도 유지한다. 자동15초 설정에서 저장 분석이3초였다는 이유로 생략하지 않으며, 명시적 심층 분석이나 저장 분석보다 긴 사용자 지정 요청은 새 탐색을 수행한다.

## 검사

`test/opening-two-family-followups.cjs`는 새433개 전체를 양쪽 색·8방향으로6,928회 자료 조회한다. 실제 자동 추천·선택지는433개 원판 전부와 주형·새 수 번호별 대표208개 색/방향 조건에서 검사한다. 대표408개22수 전수 대응, 선택6가지의 중앙 시작 부모 연결과 실제 종국, 잘못된 판·차례·부분 판의 차단도 검사한다. 종국 수는 실제 합법5목이면 회전 후의 동등한 다른 승리 끝점도 허용한다. 기존 데이터와 모델 식별자를 대조하고 작은 생성 사례로 원자료·즉시 전술 우선순위를 따로 검사한다.

`test/opening-two-family-followups-ui.cjs`는 새 수평선의 실제 추천, 두 주형의3수 선택, 반투명 돌·목록 클릭과 되돌리기,23수부터6가지 종국까지 실제 이어두기, 모바일390px, 명시적 심층 분석과 자료 밖 일반 Worker 전환을 검사한다. 공개 HTML과 실제 개인 실행 파일은 별도로 실행해 버전·오류·반영 여부를 확인한다. 공개 출력은 `dist/index.html`, 개인 출력 두 경로는 기존 외형·저장 키·기보와 같은 채택 모델을 유지한다.
