# 저항 수·지역 방어·시간 종료 추천 — v5.18.4

강제패배에서 자기 2목을 3목으로 늘리는 수보다 실제 상대 위협을 막는 수를 우선하도록 수정했다. 결과가 없는 시간 종료에서 전투와 무관한 첫 합법 칸을 고르는 경로도 없앴다. 이미 끝난 비교와 진행 중 후보를 구분해, 미완료 후보가 마지막 완료 결과를 덮지 않게 한다. 강제승 즉시 확정, 규칙·모델·신경망 입력과 빠르게 1초·자동 최대 15초·심층 최대 25초는 유지한다. 학습은 재개하지 않았다.

최근 사용자 대국의 기보는 없다. 아래는 실제 코드와 생성 국면의 재현이며, 사용자가 기억한 대국 자체의 원인을 확인했다는 뜻은 아니다. 좌표는 검사 파일의 **A1=배열 0** 표기다.

## 확인한 원인과 변경

1. Reader의 패배 fallback과 Forest의 패배 후보는 일반 국소 점수를 사용했다. 통합 최종 게이트도 반증된 후보를 모두 제거한 뒤 일반 평가로 다시 골랐다. 이 과정에서 방어보다 자기 3목 확장이 앞설 수 있었다. 공유 `resistanceMoves`는 즉시 정확한 5목, 상대 즉시 5목 방어, 상대의 즉시 역승이 없고 실제 정확한 5목 응수를 강요하는 자기 4목, 기존 상대 3목에서 생기는 합법적인 4목·양끝 위협을 줄이는 직접 차단, 조용한 확장 순으로 정렬한다. 금수나 장목으로만 위협처럼 보이는 수는 실제 4목 저항으로 세지 않는다. 유효한 4목끼리는 상대의 실제 유일 합법 방어 뒤에 자신의 합법적인 추가 4목이 남는지도 비교한다. 금수·장목과 상대 즉시 승리에 필요한 방어를 무시한 후속은 세지 않는다. 이 정렬은 안전·승리 증명이 아니다.
2. UI의 결과 없는 watchdog은 판 전체의 첫 합법 점을 사용했다. 합법인 원격 후보는 통합 최종 게이트에서도 그대로 통과했다. 이제 `fallbackResult`가 실제 돌 주변의 합법 후보와 위협 감소를 비교한다. **완료된 비교 결과나 실제 먼 곳의 즉시 승리·유일 방어는 거리만으로 버리지 않는다.** 주변 후보만 반증되고 먼 합법 수는 미검사라면 전체 패배를 발명하지 않는다. 주변 저항을 명시적으로 제공하고, 그 수의 반증과 국면 전체가 미확정이라는 표시를 함께 보존한다. 추가로 실제 Reader의 결정론적 시계 재현에서 주변 후보가 먼저 반증된 뒤 먼 `H15`가 완료 깊이 1의 24후보 비교 결과로 남는 경로를 찾았다. 먼 최종 후보와 교체 후보 최대 3개에 총 25ms의 실제 상대 VCF 검사를 적용한다. 완료된 비교도 새 반증에는 밀려나며, 원래 후보 반증 후 새 먼 후보의 검사가 미완료면 지역 저항으로 돌아간다. 검사를 완료하지 못한 것을 안전의 증거로 쓰지 않는다.
3. UI는 진행 결과의 `depth > 0`만으로 마지막 완료 결과를 덮었다. 수동 6초 경로에 완료 A(깊이 4, 점수 100), 미완료 B(깊이 5, 점수 99999)를 보내면 수정 전에는 정상 최종 메시지와 하드타이머 모두 B를 확정했다. 현재는 A를 보존한다. 이는 통제된 Worker 전달 재현이며 실제 B의 전술적 평가를 입증하는 검사가 아니다. Reader·Forest·병렬 완료 라운드에 `comparison = {complete, selected, depth, source, rootsCompared}`를 부여하고, 선택·깊이·출처·합법 PV가 맞을 때만 완료로 인정한다. 전역 깊이를 다른 후보의 완료 증거로 쓰지 않는다.

이미 반증된 A는 복원하지 않는다. 같은 완료 라운드의 대안이 있으면 그 결과를 사용하고, 없으면 위협에 대응하는 미완료 fallback으로 돌아간다. 정상 종료·오류·시간 종료에 같은 경계를 적용한다. `riskOnly`인 불리한 추정은 검증된 반증으로 승격하지 않는다. 패배 점수는 음수로 유지하고 별도의 실용적 저항 점수와 섞지 않는다. 일반 내부 탐색 캐시의 의미는 같으므로 `node-v3`를 유지하며, 통합 엔진 표시는 `unified-initiative-2-resistance-1-comparison-1`로 구분한다.

## 수정 전후 재현과 검증

- **강제패배 저항:** 내 돌 `C8 D7 D9 C7 E9 H7 G7 I9 H9`, 상대 `E8 F8 G8`, 내 차례다. 보존된 수정 전 엔진은 `E10` 자기 3목 확장을 추천했다. 현재는 `I8` 상대 3목 차단을 추천한다. 두 경우 모두 208개 합법 응수의 강제패배 증명과 음수 판정은 같다. 새 방어 수가 패배를 벗어난다고 주장하지 않는다. `test/resistance-policy.cjs`는 흑백·8개 대칭, 유효한 자기 4목 유지, 즉시 역승·금수·정확한 5목·가짜 장목 4·중복 후보·복원 등을 포함한 61개 검사를 수행한다. 기존 기보의 `G5 → 상대 G8` 뒤 `G3/G4` 추가 저항이 남는 것을 독립 규칙으로 검증하고, 추가 저항이 없는 `G8 → 상대 G5`보다 우선한다. 이 보완으로 기존 `G5` 회귀 단언을 그대로 통과했다.
- **우측 전투 fallback:** 내 돌 `N7 N8`, 상대 `J5 K5 L5`에서 `B2`나 내 `N6/N9` 3목 확장은 상대 `I5/M5` 양끝 공격을 허용한다. 독립 규칙으로 이를 확인하고 `I5/M5` 선점이 그 양끝 위협을 줄이는 것을 확인했다. 구 최종 게이트는 미완료 `B2`를 유지했고 현재는 방어 후보를 선택한다. `test/local-fallback.cjs`는 흑백·8개 대칭 16개와 실제 먼 승리·필수 방어, 금수 대안, 부분 반증과 위험 추정의 정직한 처리를 검사한다. 실제 반증이 있는 완료 `B2/C2/D2`는 독립 증명 검사 후 지역 방어로 바꾸고, 상대 강제승이 없는 별도 조용한 국면의 완료 먼 후보는 보존한다. 위 실제 Reader의 미완료 스크리닝·완료 비교 경로도 다시 검사한다.
- **완료 결과 보존:** `worker-lifecycle`은 수동 6초(내부 예산 5,640ms), 자동·심층에서 정상 종료·오류·하드타이머와 같은/다른 깊이의 미완료 B를 검사한다. A의 반증, 완료 대안, 명시적 미완료 우선, 취소와 늦은 결과도 구분한다. 병렬 탐색 자체는 이미 동일 깊이 전체 라운드가 끝난 뒤 게시하고 있었으며, 개별 역사 분석도 후보 평가가 끝난 뒤 게시했다. 이 둘을 미완료 B 노출의 원인이라고 주장하지 않는다.
- **실제 Edge:** 공개 기본 외형·모델 없는 생성 fixture에서 빠르게·자동·심층 × 흑백 6개가 상대 3목 차단과 강제패배 표시를 유지했다. 각 208개 패배 응수를 별도 규칙과 DAG로 다시 검증했다(총 1,248개). 실제 6초 하드타이머 두 조건에서는 모든 Worker 메시지 보류 시 지역 방어·미확정 표시, 실제 완료 A 이후 미완료 B 주입 시 A 보존을 확인했다. 후자는 전달만 통제했고 승리·패배 증명을 조작하지 않았다. 모든 경우 합법 수·PV·보드 복원·완료 1회·Worker 0개였다.

기존 검사 중 두 전제를 보완했다. 패배 후보의 점수를 임의의 `99`로 고정하던 단언은 새 저항 재정렬과 충돌해, 음수 국면 값·별도 유한 저항 점수·합법성과 비교 미완료 표시를 검사한다. 서로 깊이가 다른 과거 후보 행으로 C를 승격하던 검사에는 실제 동일 깊이 완료 라운드를 공급하고, C의 원래 점수·깊이 보존 단언은 유지했다. 비교·증명 조건을 완화하지 않는다. 초기 전체 검사에서는 즉시 5목 패배 때의 후보에 무관한 세 번째 수를 넣는 문제와 금수 방어점 경고 문구를 덮는 문제도 발견했다. 합법 끝점 후보와 금수 좌표·경고를 보존하도록 소스를 수정했고 기존 단언을 유지했다. 추가 4목의 후속 저항을 놓친 `G5` 문제 역시 소스를 보완했으며 좌표 단언을 삭제하지 않았다. 과거 Worker 문맥 fixture에는 단순 깊이 4 대신 실제 완료 비교 메타데이터와 같은 출처의 후보 행을 명시했다. 교체된 추천의 낡은 승리 증명은 여전히 제거하며, 별도로 완료된 비교 행은 제한 탐색으로 구분한다.

최종 소스로 npm test의 엔진·규칙·캐시·기보·전략·Worker 단계가 통과했고 통합 시나리오 35개는 실패 0개였다. 이후 과거 counter-worker fixture의 완료 증거·문맥 fallback 누락 때문에 전체 명령은 종료 코드 1이었다. 해당 통제 fixture를 새 계약에 맞추고 npm run test:g13-counter와 남은 npm run test:learning을 각각 종료 코드 0으로 끝냈다. 전체 검사 항목은 이 단계 실행으로 모두 확인했으며, 실패한 전체 명령을 종료 코드 0이라고 보고하지 않는다. 학습 검사는 생성·임시 자료를 사용하고 실제 중단 실험을 켜지 않는다. 실제 Edge의 기존 모드·강제승 16경로·후보 인증 8경로·금수 및 역공 10경로와 새 저항·6초 종료 8경로도 통과했다. 최종 원격 반증 검사 추가 후 새 Edge 8경로를 재검증했다.

이 변경은 종료 경계와 실용적 저항 선택의 개선이다. 제한 탐색에서 모든 3목이나 장기 역공을 발견한다는 보장은 없고, 실제 후속 수읽기로 검증된 더 좋은 결과는 단순 지역 규칙보다 우선한다. 장기 대국 기력 평가를 새로 실행한 결과로 확대하지 않는다. 상세 로그·수정 전 원본과 비교 결과는 ignored `work/resistance-timeout-20261026/`에 둔다.

## 기존 자료와 배포

기존 run·기보·경험 DB·체크포인트·채택 모델을 새 실험으로 덮어쓰지 않는다. 기존 실험·활성 모델·개인 외형의 보호 파일 21개 SHA가 작업 시작과 같은 것을 확인했다. trial 95 / cycle 1의 934/6,800 미완료 평가는 stopped 상태로 보존하며 이번 변경을 채택 근거로 쓰지 않는다. 이전 소스 식별자는 `6ad08b5cc1f6d326830ae296c38045d96121a05e371124b1fd1e5600d2a43f87`, 수정 소스는 `68a60910d822dab3819915bb39454e0ce059ed35af65cb978f788c1855fef20d`다. 나중에 이번 엔진으로 경험과 유효 가중치를 이어갈 때는 정상 `--from-run`을 통한 새 run·새 평가가 필요하다.

공개 `dist/index.html`과 개인 외형·기존 저장 키를 유지하는 로컬 `outputs/omok.html`을 구분한다. 학습 원본·미채택 후보·개인 외형·로컬 HTML은 Git에 올리지 않는다.
