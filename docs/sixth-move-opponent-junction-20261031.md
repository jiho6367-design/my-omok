# 후공 6수의 상대 연결 대비 · 2026-10-31

공개 v5.18.11은 흑 `H8·I7·I6`, 백 `G7·G9`인 다섯 돌 배치에서 백의 6수 후보를 평가하는 방식을 보완했다. 같은 배치를 만드는 합법적인 검사 수순은 `H8 G7 I7 G9 I6`이다. 사용자 사진의 F8 추천과 상대의 다음 H6 꺾임을 검사 사례로 삼았다.

F8 뒤 흑 H6은 세 방향에서 합법적인 준비수와 열린 4목을 만들 수 있다. 각 축에 정확한 5목 끝점 두 개가 실제로 존재하는지 확인한다. 백 H9는 H6의 세로축 끝을 닫아 이 조건을 줄인다. 백 G8 뒤의 같은 H6은 백 G6의 즉시 열린 4목 반격을 허용하므로 같은 위험 감점을 주지 않는다.

이 검사는 돌 12개 이하의 가까운 연결에 한정한다. 합법 준비수·4목·끝점의 근거를 보존하고, 자기 강제 차단 요구나 즉시 승리·열린 4목 반격이 있으면 상대의 조용한 연결 위험을 적용하지 않는다. 같은 후보군 전체의 검사가 완료됐을 때만 유한 위치 평가에서 180점을 낮춘다. 시간 종료로 일부만 검사했으면 전체 감점을 버린다. 단일·병렬 후보 비교는 같은 근거와 점수 규칙을 쓴다.

180점은 기존 전략의 열린 3목 축 단위와 같은 크기의 제한된 선호다. 후보를 금지하거나 F8을 강제패배로 판정하지 않는다. 연속된 자기 준비수의 기하학적 가능성은 교대로 진행되는 강제승 증명이 아니다. 상대의 모든 장기 응수를 해결했다는 의미도 아니다.

## 실제 앱 확인

기존 채택 모델과 동일한 다섯 돌 배치, 후공, 자동 최대 15초로 확인했다. 엔진·모델을 실행하는 병렬 Worker 경로의 기존 버전은 F8, 수정 버전은 H9를 추천했다. 두 실행 모두 24개 후보의 깊이 7 비교를 완료했다. 표시 깊이가 달라지는 별도의 수읽기 연장은 최종 수정에 포함하지 않았다.

실제 Edge의 공개 HTML에서도 백 차례·다섯 돌·자동 요청 15초/내부 예산 14.1초를 확인했다. 최종 H9는 약 12.96초에 반환됐고, 브라우저 오류는 없었다. F8 후보에는 H6 연결 근거와 180점 조정이 남았다. 승리·패배 증명 표시는 모두 없었다. 이는 해당 장치와 국면의 확인이며 전체 기력 향상이나 무패 보장이 아니다.

## 회귀 범위

생성한 작은 국면으로 회전·반사·색상 교환 16개를 검사한다. 세 축의 준비수·열린 4목·정확한 5목 끝점은 별도 규칙 구현으로 대조한다. 선제 차단, 실제 반격, 즉시 승리, 밀집 국면 제외, 검사 중 예외의 보드 복원, 부분 검사 전체 취소와 단일·병렬 점수 일치를 확인한다. 생산 학습 데이터나 실험 모델을 CI 입력으로 사용하지 않는다.

기존 채택 모델과 원본 평가 식별자는 유지했다. 이 업데이트는 엔진 소스 수정이며 새로운 모델 채택을 기록하지 않는다. 기존 미완료 실험과 개인 외형은 공개 변경에 포함하지 않는다.
