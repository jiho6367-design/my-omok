# K4 작은·큰 사각형 연구와 초반 자동 시간 배분

실험 시작 2026-10-26, 최종 24판 완료 2026-10-27(KST). 선공 첫 수 K4를 고정하고 후공 2수를 작은 사각형 테두리 8곳(J3–L5), 큰 사각형 테두리 16곳(I2–M6)에 각각 두었다. 양쪽 모두 앱의 자동 모드 최대 15초를 사용한다. 첫 두 돌만 지정하며 3수부터 엔진이 선택한다. 실제 합법적 정확한 5목 또는 판 가득 참으로만 대국을 끝낸다.

## 확인한 문제

K4 주변에도 실제 돌과 오목 창을 기준으로 후보를 생성하므로 중앙 전용 구현은 아니었다. 기준 엔진 v5.18.7로 완료한 첫 6판은 선공 5승·후공 1승이었다. J3(27수), K3(45수), L3(29수), J4(29수), L4(63수)에서 선공이 이겼고, **K4→J5에서는 40수에 선공이 졌다**. 나머지 18판은 진단을 위해 저장·중단했다. K5는 25수, L5는 13수, 다른 16판은 0수이며 무승부로 계산하지 않는다.

J5 패배의 즉시 방어 누락은 0건이었다. 25수 N5 뒤 실제 백 O4가 놓인 국면에서는 합법적인 흑 199수 모두 패배함을 별도 검증기로 확인했다(22,497 DAG 노드·30,068 방어). 25수 진입에서는 201수 중 197수만 반증했고 O4·N7·E8·O8은 제한 검사에서 미해결이었다. 따라서 25수 N5의 패배는 확인했지만, 그것을 최초 회피 가능 실수나 다른 수의 안전 증명으로 부르지 않는다.

후보 누락도 원인과 구분했다. 실제 후속 `K10→G8→F9→G9`에서 G9가 좁은 자식 16개 밖에 있었으나, 같은 깊이·실제 ply에서 G9를 추가해도 완료 평가 712.6366은 같았다. 다른 경로에서 같은 국면으로 합쳐졌기 때문이다. 이 근거로 후보 폭·연결 점수·12돌 경계를 바꾸지 않았다. 해당 조사에서 압박·템포 보너스의 잘못된 적용도 확인하지 못했다.

## 초반 시간의 제한과 대안 대국

기존 자동 계획은 양쪽 돌이 하나씩 놓인 국면을 돌이 적다는 이유로 3초에 제한했다. K4→J5의 실제 3수는 M6, 완료 깊이 4, 평가 약 +302.99였다. 같은 모델과 동결 HTML을 새 브라우저에서 실행하고 이 국면의 예산만 명시적으로 15초로 바꾸면 K6, 완료 깊이 6, 평가 약 +189.60을 골랐다. 점수는 승률이 아니며 서로 다른 깊이의 점수를 기력 차이로 환산하지 않았다.

이 실제 15초 분석의 3수 K6에서 분기하고, 이후 동일 엔진의 기본 자동 모드로 진행한 별도 대국은 **25수에 선공 승리**로 끝났다. 3수 이후 캐시는 새로 시작했다. 이 파일럿은 원본 두 수와 실제 분석 결과를 출처 해시로 연결한 한 건의 대안 실험이다. 기본 자동 계획으로 처음부터 진행한 대회나 K6의 필승 증명으로 세지 않는다.

K3에서는 3수 J4·완료 깊이 4·3초로 45수에 이긴 기준군과 달리, 15초·완료 깊이 6에서 J5를 고른 1차 수정본이 74수에 졌다. 더 긴 제한 탐색이 항상 더 강한 착수를 고르지는 않는다. 이 승패만으로 3수 J5가 최초 실수나 강제패배 수라고 증명한 것도 아니다.

## 기각한 2차 시간 가설 v5.18.9

양쪽 돌이 하나씩 있을 때, 수가 직선으로 바로 붙었고 자기 첫 돌을 지나는 네 방향 모두에 상대 돌을 피하는 판 안의 5칸 창이 있으면 기존 짧은 계획을 유지한다. 수가 벌어졌거나 한 방향이라도 그런 창이 없으면 최대 15초를 배정한다. 창의 존재는 가능한 공간의 기하 정보이며 실제 공격·안전·강제승 증거가 아니다.

K4에서 이 기준은 K3·J4·L4에 기존 3초, 나머지 21곳에 최대 15초를 배정한다. K5는 상대 돌을 피하는 세로 5칸 창이 없으므로 긴 비교를 유지한다. 수·색·좌표를 지정하는 예외를 넣지 않았으나, K3 회귀를 본 뒤 고른 **사후 시간 배분 가설**이라는 한계는 남는다. 일반 기력 개선은 별도 대국 결과로 판단해야 한다.

이 버전은 작은 고리 8판에서 선공 3승·후공 5승으로 끝나 목표를 충족하지 못했다. 16판은 저장·중단했으며 I2는 12수, J2는 6수, 나머지는 0수다. K3는 40수, J5는 76수에 선공이 졌다. 기하 분류의 기능 검사가 통과해도 기력이 개선되는 것은 아니므로 이 정책을 배포 후보에서 제외했다.

J5의 처음 열 수가 같았던 두 실행도 11수에서 갈렸다. 1차 수정본은 완료 깊이 8에서 I4를 골라 이겼지만, 2차 버전은 깊이 7에서 J3를 골라 이후 졌다. 시간제한 탐색의 완료 깊이·이력과 당시 계산 부하가 결과에 영향을 줄 수 있다. 이번 자료는 한 번의 승리나 단순한 시간 증가를 안정적인 강화로 볼 수 없다는 반례다.

## 두 패배의 확인 범위와 남은 조사

I4는 70수 백 C5, K6는 56수 백 H13의 실제 정확한 5목으로 끝났다. `audits/release-i4-static.md`와 `release-k6-static.md`는 저장된 분석·실제 응수·미완료 반복을 구분한 정적 메모다. I4의 첫 저장 흑 패배 표시는 53수 N4, 첫 백 승리 표시는 56수 F9였다. K6의 첫 저장 흑 패배 표시는 43수 I9, 첫 백 승리 표시는 44수 I8이었다. 이 표시의 위치를 최초 회피 가능 실수로 세지 않는다.

별도 표준 감사 `release-i4-proof.json`은 흑 43·47·49·51·53·55수, `release-k6-proof.json`은 흑 31·33·35·39·41·43수를 각각 국면당 최대 1초·전체 최대 10초 범위에서 검사했다. I4의 55수 I7 뒤와 K6의 43수 I9 뒤에는 실제 상대 차례의 승리 증명을 검증했지만, 그 착수 전부터 모든 합법 수가 패배였는지 또는 안전한 다른 수가 있었는지는 확정하지 못했다. 두 감사 모두 `earliestConfirmedError:null`이며, 이는 오류가 없다는 뜻이 아니라 제한 검사에서 최초 회피 가능 실수를 입증하지 못했다는 뜻이다.

I4에서는 흑 45수 E6으로 백 D6 응수를 끌어낸 뒤의 후속 공격과 백 50수 G9를 함께 비교했다. K6에서는 백 44수 I8의 저장 11수 PV가 실제 44~54수와 일치하는 긴 강제 공격 꼬리를 조사 대상으로 삼았다. 필수 방어가 준비 수 예산을 소모하지 않는 현재 구현을 준비 수 회계 버그라고 부르지 않으며, 이전 guard의 미완료·남은 깊이·발견 범위의 영향을 구분해야 한다.

이 조사에서 긴 강제 꼬리의 발견 범위를 넓히는 별도 로컬 시제품도 제한 비교했다(`diagnostics/i4-quiet0-tail-20261026T162149Z/report.json`). I4의 45수 E6·47수 K7에서는 기존 범위와 확장 범위가 모두 완료·무증명이었다. I4의 49수 I8과 K6의 39수 N8·41수 M2는 미완료·미해결로 남았다. 새 승리 인증서를 얻지 못해 이 확장은 배포에서 제외했고 v5.18.10 소스는 그대로 유지했다. 기록된 CPU 시간은 14.391초지만 다른 기보 재생과 겹쳤으므로 속도 개선·악화의 근거로 쓰지 않는다. 이 제한된 무증명·미완료 결과는 해당 수의 안전 증명이 아니며, 확장의 모든 국면 효과를 부정한 것도 아니다.

I4·K6 패배의 정확한 수정 원인과 최초 회피 가능 실수는 아직 미해결이다. 안전한 대안이나 필승 수를 입증하지 못했으므로 두 대국의 전략 문제가 해결됐다고 결론 내리지 않는다.

## 검사와 식별자

- 최종 시간 정책은 두 색·D4·중앙·K4·가장자리 112개 생성 국면에서 실제 설정 해석기의 예산·내부 여유·시계 제한·다른 모드·보드 불변을 검사했다. 다른 돌 수, 즉시 승리·유일 방어도 유지된다. 기각한 기하 정책의 992개 분류 검사와 기력 평가는 구분한다.
- 새 합법성 빠른 경로는 15·19판의 독립 판정 12,168건, 이웃 계수 상태 406건, 생성 모델/모델 없음·패턴표 유무·색 교환의 완료 탐색 비교 16건을 통과했다. 점수·수순·노드가 기존 정밀 경로와 같고 기한 중단 뒤 보드 복원과 재사용도 확인했다.
- 1차·2차 버전의 각 64개 회귀는 통과했지만 2차 정책의 대국 성적은 나빴다. 최종 v5.18.10은 추가 검사를 포함한 전체 65개 회귀를 종료 코드 0으로 통과했다(`engine-v5.18.10-complete-regression.log`). 실제 Edge 회귀도 `native-regression-v5.18.10/`의 두 묶음 16건·352건을 통과했다. 기능 검사 통과와 최종 대국의 기력 평가는 구분한다.
- 최종 검사 중 100ms에서 F5만 반환해야 한다는 과거 검사가 실패했다. F7도 합법 상대 198응수 전부를 포함한 강제승임을 별도 검증했다. 미완료 100ms 결과에는 승리 표식을 강요하지 않고, 실제 빠르게 1초 모드에서는 반환 수의 합법 PV와 독립 승리 인증서를 요구하도록 검사를 고쳤다. 기존 F5의 VCF와 F7의 전체 응수 증명도 모두 유지해 검사한다.
- K4 24개 개장·고리 소속·첫 수·모드·해시·실제 종료와 상충 재개 설정의 생성 검사를 통과했다. 기존 H8 기록도 원본을 변경하지 않고 읽을 수 있다.
- 보고서는 8개/16개 고리별 완료와 선후공 승수를 표시한다. 실제 Edge에서 24행·225칸·기보 선택·이전/다음·오류 없음을 확인했다. CI는 작은 생성 기보를 사용한다.
- 패배 진단 도구는 `--player=1`로 선공도 검사한다. 자기의 즉시 승리를 방어 누락으로 오판하지 않고, 이미 끝난 승리에 가상의 상대 차례를 추가하지 않는 생성 검사를 통과했다.
- 보고서 CLI의 기존 출력 경로 누락도 수정했다. 입력 manifest·앱·요약·중단 파일·games 하위와 출력 별칭·hardlink를 쓰기 전에 거부한다. 일반 재생 HTML/JSON 재생성은 유지하며 실제 원본을 변경하지 않는 생성 검사와 별도 검토를 통과했다.
