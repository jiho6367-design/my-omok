# Keeping the first verified live strategy

The live session keeper preserves a complete winning certificate after the user actually plays its selected move. It follows the same conditional graph for the opponent's real reply. A representative PV alone cannot create a quiet strategy.

Current immediate exact-five wins and mandatory blocks take priority. Otherwise, actual move-record order decides between an already selected registered strategy and a live strategy. A newly matching registered row or a later search PV cannot replace an earlier selected certificate. Undo before the selected move deactivates that root; redo restores the same root. A different own move invalidates its continuation. A new game has a separate identity.

The analysis job freezes its exact board, ordered events, attacker, first player, engine source, model and requested budget before it runs. Missing provenance stays null. Historical proof work is separate from current lookups: continuing a strategy reports zero current search depth, nodes and time, and does not set a new live `proven` flag.

Predicted replies use the same job binding. A speculative result has no selection authority until the actual opponent move, complete ordered history, board, game and attacker match its issued job. A serialized token cannot create that authority. Deep or longer custom analysis settings keep an already selected live strategy; choosing another own move ends its applicability.

An isolated Worker independently verifies all conditional branches under `15x15-exact5-both33-v1`. The browser stores original canonical result bytes, the verified graph and provenance in one IndexedDB transaction before exposing a committed reference. Actual followed-root selection is a separate record. Reload and imported backups require full verification again; an incomplete reservation or a conflicting tab fails closed and preserves existing evidence. Existing localStorage keys and old records are not automatically migrated.

The selected main result and native serial/parallel outputs have separate canonical bytes, hashes, source scopes and actual phase budgets. The actual serial and parallel dispatch snapshots independently bind their observed model hashes and native budgets. Worker source digests read the exact Blob already used to create each execution URL, avoiding a second synchronous full-source UTF-8 encoding on the UI thread; unknown phase provenance stays null. One output is never relabelled as another. Scope headers have their own portable JSON canonical digest in both evidence and reference rows, in addition to the Worker evidence digest. Restore, durable-reference conversion, export and import verify those equal headers before reading native source bytes. A verified strategy can continue in the current window while durable storage is incomplete; it has no committed pin. Only after durable byte verification may this keeper's newly followed event replace a top-level proof larger than 4 KiB with a reference to those original bytes. Historical metrics, PV and other fields remain unchanged. Old events and failed writes retain their original proof fields. Proof-inclusive JSON backup keeps the existing 10 MB limit.

Inactive games release their completed, durable in-memory capabilities, without deleting IndexedDB evidence, references or records. Returning to a game recreates the same root only after full verification. The Worker capability limit remains 32.

The certificate limits are 64 MiB combined canonical raw evidence, 8 MiB compact graph, 65,536 nodes, 262,144 input edges and a 5-second independent rule-verification budget. Expanded JSON traversal also stops at one million values and conservative byte limits; single strings and keys are checked before complete canonical output. These are serialization and verification limits, not a total JavaScript memory or end-to-end wall-time guarantee. The separate registered-opening lookup horizon and native continuation-data caps do not change. General session histories support at most 225 stones; typed timeouts are supported before a root, while a timeout after that root ends its applicability. A compiler or rule-verification limit prevents a retained capability. An archive byte limit or storage failure can leave an already verified strategy available only in the current window, without a committed reference. The original analysis and record are preserved.

Supported certificates are complete all-legal-replies roots, exact five and fully verified forcing-four/VCF lines. An aggregate or PV-only `opponent-complete-loss` without its complete tree is preserved as ordinary analysis and cannot retain a strategy. A rejected or unsupported certificate clears its tentative selection marker and returns to normal analysis. A declared non-house ruleset bypasses generic capture and lookup rather than receiving a house-rules identifier.

`node test/live-proof-keeper.cjs` and `node test/live-proof-resource.cjs` use small generated certificates and the original rule verifier in a real Node Worker. They do not depend on private runs, production archives, browser installations or adopted local models. Real browser IndexedDB, quota-fault, UI, export/import and private-game checks are separate integration evidence.
