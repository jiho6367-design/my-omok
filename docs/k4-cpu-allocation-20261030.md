## 같은 브라우저에서 풀 3개와 5개 비교

논리 CPU 16개인 PC에서 Edge 156.0.4314.42 한 브라우저로 자동 최대 15초 분석을 8회 순차 실행했다. K5 23수 직전과 K6 43수 직전의 실제 기보 국면을 사용했다. 풀 3개/5개 외 일반 분석 Worker 하나도 함께 실행되며, 후속 검증 Worker는 풀이 끝난 뒤 실행된다. 풀 선택에만 쓰는 navigator 입력을 6/8로 제어했고 실제 PC의 논리 CPU 16개와 구분했다. 각 엔진 탐색 요청에는 코어 수 필드를 전달하지 않았다.

빈 검색 메모리(cold)와 직전 분석의 완료 노드 메모리를 가져오는 경우(warm)를 구분했다. 분석마다 Worker를 새로 만들기 때문에 warm를 Reader 내부 후보 메모의 분석 간 재사용으로 해석하면 안 된다. Worker 생성·입력 복제·후보 계획은 측정에 포함하고, 페이지·테이블 준비는 모든 경우 같은 경계 밖에서 처리했다.

8회 모두 요청·적용 상한은 15초, 내부 탐색 예산은 14.1초였다. 다음 라운드를 끝내지 못했을 때 직전 완료 비교를 보존하고 그보다 일찍 반환했다. 입력 보드·착수·주요 수순의 합법성, 실제 모델 전달, 모든 Worker 종료를 확인했다. 최종 표시는 `UNRESOLVED`이며 안전·필승 증거로 세지 않는다.

표의 마지막 완료 라운드 노드는 그 라운드 작업의 합이다. 최종 결과의 `nodes`는 후속 검사의 노드도 포함할 수 있어 별도 값이다. 예를 들어 첫 행의 완료 라운드는 1,111,382노드이고, 검사까지 포함한 최종 결과는 1,116,849노드다.

완료 작업 누적 노드는 실제 할당 식별자와 맞는 완료 메시지만 한 번씩 합산한 값이다. 다음 미완료 라운드에서 끝난 일부 작업과 반복 계산을 포함하므로 전체 후보를 같은 깊이까지 비교한 노드 수나 순수한 속도 향상률과 다르다. 풀 5개는 이 표에서 완료 작업량이 더 많았지만 같은 메모리 조건의 완료 깊이와 추천수는 풀 3개와 같았다. 이 두 국면만으로 전체 기력 향상, 일정한 속도 향상률, CPU·GPU 사용률을 주장하지 않는다. 추가 소스 변경 없이 현재 풀 정책을 유지한다.

## 심층 분석과 남은 UI 경로

처음 모드 묶음 검사는 첫 K6 심층 분석의 완료 콜백을 28초 안에 관측하지 못해 실패했다. 종료 직전 상태가 없어 당시 엔진이 계속 실행 중이었는지, 검사 시작 시 설정창 닫힘 이벤트와 재분석이 겹쳤는지 확정할 수 없다. 실패 기록은 보존했다.

설정창의 실제 닫힘을 기다리고 종료 전 관측을 추가한 별도 검사는 같은 K6 심층 분석 한 번만 실행했다. 약 23.346초에 완료 깊이 6의 비교를 반환했고, 심층 적용 상한 25초·내부 예산 23.5초와 직전 완료 비교 보존을 확인했다. 보드·주요 수순·모델·Worker 종료가 정상이며 원생 Worker 오류와 페이지 오류가 없었다. 이 성공을 앞선 실패 원인의 확정이나 전체 모드 묶음 통과로 확대하지 않는다.

나머지 네 검사는 별도 실행으로 통과했다. 실제 심층 Worker를 만들고 요청을 보낸 다음 화면의 빠르게 전환 이벤트를 발생시켰다. 기존 Worker는 즉시 종료됐고, 약 1.019초에 빠르게의 합법적인 결과를 받았다. 취소된 원래 콜백은 호출되지 않았다. 늦은 원생 응답이 실제 도착했다는 증거가 없으므로 그 응답의 거부까지 검증했다고 주장하지 않는다.

작은 생성 국면에서 이미 5목인 돌을 주는 단축 경로를 피하고 실제 Worker·같은 모델을 사용했다. 빠르게 66.4ms, 자동 60.6ms, 심층 57.7ms에 모두 `PROVEN_WIN`을 반환했다. 독립 규칙 검사에서 추천 수 뒤 두 곳의 합법적인 승리 지점이 생기는 것을 확인했다. 세 결과 모두 완료 콜백 한 번, 보드·주요 수순 보존, 페이지·원생 Worker 오류 없음, 모든 Worker 종료를 확인했다. 이 작은 사례가 모든 복잡한 강제승의 즉시 검출을 보장하지는 않는다.
