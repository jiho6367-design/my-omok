# 후보6의 방어 후보 보존과 성능 검증 실패

후보6(v5.18.23)은 J6 연구 국면에서 빠졌던 방어 후보의 평가 영향을 재현하고 일반적인 보존 규칙을 추가했다. 그러나 원래 34돌·1,500ms 검사에서 완료 깊이1을 만들지 못했다. **후보6은 기능 검증 실패·미채택 상태다. 핵심8판과 나머지16판을 시작하지 않았으며 기존 앱을 유지한다.**

이 문서는 [후보5의 핵심8판 결과](k4-candidate5-computation-20261030.md)에 이어 사용자가 승인한 추가 후보 한 개와 J6 진단 최대30 CPU초의 연구를 정리한다. 기존 기보·모델·실패 기록은 보존했다.

## 재현한 원인 기여

J6 기보의 흑21수 O7→백22수 N7 뒤, 앞선 탐색은 흑의 후속 J5를 높은 전술 점수로 평가했다. 같은 국면을 더 깊게 분석한 실제 흑23수에서는 H7을 골랐고 J5의 평가는 낮아졌다. 이것만으로 부모·자식 탐색 오류나 최초 패착을 확정하지 않고 남은 깊이와 자원을 맞춰 비교했다.

부모 탐색과 같은 남은 깊이의 자식 비교에서 J5의 원래 점수 `9,999,987`이 재현됐다. **실제23수는 흑 H7이며, 여기서 진단한 백 H7은 흑 J5 후보 뒤의 가상 응수다.** 그 가상 국면의 백 잎 후보에는 L3이 있었으나 H7은 없었다. 흑 K4–J5–I6의 연속3에 대해 L3과 H7은 상대가 다음 열린4를 만드는 양끝이다. 차단 대표를 압축하는 과정에서 그중 한 곳이 빠진 것이다.

정확히 그 잎에 **합법적인 H7 한 개만** 더하고 깊이·확장 자원·준비 비트·모델을 유지한 사적 대조에서 J5 점수가 `-604.8245372609263`으로 바뀌었다. 이로써 H7 누락이 이 분기의 과대평가에 기여함을 확인했다. 깊이 차이만으로 설명하거나 좌표 가산점을 주는 접근을 사용하지 않았다.

이 수치는 제한 탐색 평가다. 필승·강제패 증명, H7의 전체 응수에 대한 안전 증명, 최초로 피할 수 있었던 패배 분기 또는 J6 승리 대안의 증거는 아니다. 특히 앞선 최종 K3의 PV에는 이미 백 E8이 있었으므로 J6 전체 패배를 “상대 첫 수를 못 봄”으로 설명하지 않는다.

## 단일 일반 규칙 D

후보6은 기존 공격·차단·겸용 대표와 실제4목 F, 사용 가능한 연속 열린3 대표 G를 원래 순서대로 보존하고, 다음 조건의 방어점 D를 함께 남긴다.

- 현재 자신이 합법적으로 둘 수 있는 빈 점이다.
- 상대도 그 점에 합법적으로 둘 수 있다.
- 상대가 그 점에 두면 한 축의 연속4가 되고, 그 축의 양끝이 모두 합법적인 정확한5목 완성점이다.

양끝 확장과 사이 빈칸 메우기를 포함한다. 막힌 끝·보드 밖·장목만 만드는 끝점·3·3 금수인 가상 착수는 해당하지 않는다. 좌표별 조건이나 점수 조절은 없다. 기존 즉시 승리·필수4목 방어의 우선순위, 색별 준비 자원, 공통 확장 상한, 준비 소진 뒤 실제4목 두 후보 제한은 유지한다. D에 포함됐다는 사실은 안전이나 승리의 증명이 아니다.

수정 후보의 고정 작업 비교에서는 탐색 TT를 끈 경우, 루트 순서·내부 순서를 뒤집은 경우, 준비 후보 메모를 재사용한 경우에도 J5와 H7의 값이 각각 `-604.8245372609263`, `-41.63343914386053`으로 일치했다. 여기서 TT 비활성화는 전술 캐시 전체를 끈다는 뜻이 아니다. 실제5ms 잎 VCF 모드는 별도로 기록했으며 고정 작업 값과 같아야 한다는 조건을 만들지 않았다. 이 유한 대조를 전체 기력 보장으로 확대하지 않는다.

## 완료한 생성 검사와 관측 검사 정합화

새 작은 생성 회귀 검사는 단독 실행에서 통과했다. 회전·반사·색 교환16개와 경계 사례14개에서 독립적인 네 칸 창 열거로 D를 대조했다. 대표 잎의 실제 후보 조합, 기존 F/G 보존, 즉시 승리·필수4목 방어, 준비·확장 자원, 차가운/따뜻한 메모 및 이식된 메모, 실제 착수 중 시간 종료의 보드·특징 복원도 검사했다. 생성망과 신경망 없음 조건을 사용했으며 원본 대국이나 채택 모델 자료를 CI fixture로 복제하지 않았다.

검증 도구의 첫 실행은 Windows 경로 구분자를 정규화하지 않은 빌드 해시 충돌로 build 뒤 중단됐다. 그때 실제 Reader 검사는 실행되지 않았다. 새 도구에서 경로와 현재 빌드 백업 처리만 고쳤고 원본 실패를 보존했다.

다음 전체 검사에서는 기존 forcing-horizon 관측기가 최종 후보 전체를 세 개로 가정해 42번째 명령에서 실패했다. 기존 세 개 제한은 원래 공격·차단·겸용 대표에 유지하고, 최종 조합은 독립적인 F/G/D 완전성·합법성 검사로 구분했다. 원래 자원·착수 순서·캐시·복원 단언을 보존했으며 엔진 정책을 다시 바꾸지 않았다. 두 중단의 실제 자식 종료를 확인하고 비용을 같은 원장에 이어 기록했다.

## 통과하지 못한 실제 시간 조건

최종 전체 검사에서는 앞의57개 명령을 통과한 뒤 58번째 원래 Reader 검사에서 `depth >= 1` 단언이 실패했다. 원래 34돌 보드, `analyze(1,1500)`, 검사 순서와 단언을 바꾸지 않았다. 대상 호출이 반환한 뒤만 관측했으며 추가 대상 호출로 재시도하지 않았다.

후보6은 보드를 복원하고 반환했으나 선별42개 상태에서 완료 비교를 만들지 못했다. 이는 실제 성능 통과 조건의 실패다. 관측 도구 오류로 처리하거나 시간을 늘려 합격시키지 않았다. 후보 검증에도 tick이 쓰이고 추가 규칙으로 그 집계 범위가 달라졌으므로 원시 노드 수를 연산 처리량이나 속도 향상 비율로 비교하지 않는다. JIT·GC나 특정 하드웨어 병목을 분리 측정한 결과도 아니다.

전체78개 검사는 완료되지 않았고, 뒤의 브라우저368단계와 NN 점수705개·특징 벡터1,410개·시간 종료 복원6개 검사는 진입하지 않았다. 단독 생성 검사 통과와 기존57개 명령 통과를 전체 기능 검증 통과로 표시하지 않는다.

## 보존 상태와 한계

승인된 여섯 후보를 모두 사용한 상태에서 추가 정책 수정·핵심8판·24판 재검증·앱 반영을 진행하지 않았다. 기존22승의 개별 보존, I4/K6 전환, J6의 실전 개선은 후보6에서 확인하지 못했다. 기존 배포판 v5.18.10과 사용 앱, 모델8119·규칙·자료를 유지한다. 미채택 후보의 소스·관련 시험·빌드·원본 대국·실패와 감사 영수증은 로컬에 보존한다. 이번 공개 범위는 연구 요약이다.

원인 재현·수정 제작·생성 검사·시간 조건·실전 평가를 구분했으며, 추가 진단의 실패·감독·감사 비용을 삭제하거나 원장을 초기화하지 않았다. 최종 종료 감사까지 포함한 측정 비용과 명시적 꼬리 예약은 승인된30 CPU초 안에 있다. 필수 전체 기능 검사의 별도 비용 범위도 유지한다. 최종 감사에서 소유한 프로세스의 종료와 잠금 해제를 확인했다.
