# 후보5의 계산 비용 보완과 핵심8판 결과

후보5(v5.18.22)는 계산 비용 보완과 전체 기능 검사를 통과했으나, 새 종료 기준의 핵심8판에서 **선공7승·후공1승**으로 최종 통과 조건을 충족하지 못했다. J6의 기존 선공 승리를 보존하지 못해 나머지16판은 진행하지 않았다. **후보5는 미채택이며 기존 앱을 유지했다.** 대국 결과의 기준은 2026-10-29 21:41:17 UTC의 최종 보고다.

## 변경 범위와 식별자

[후보4](k4-candidate4-horizon-20261030.md)는 단독 34돌 검사에서는 깊이1을 완료했으나 전체 흐름에서는 같은 필수 조건을 만족하지 못했다. 그 실패를 보존하고, 사용자가 추가 승인한 후보 한 개와 성능 진단 최대30 CPU초 범위에서 후보5를 준비했다.

기존 정책은 공격·차단·겸용 후보에 실제 4목 후보 전체(F)와 검증된 연속 열린3 대표 최대 한 개(G)를 함께 남긴다. 후보5는 G의 임시 착수 전에 **정확히 연속3이 되고 양끝이 빈 모양인지** 먼저 읽는다. 이 필수 모양이 불가능한 후보만 임시 착수·승리점 계산 전에 제외한다.

모양을 통과하면 기존 합법성·후속4목·정확한5목 끝점 검사를 그대로 수행한다. 기존 후보 순서, F 전체, G의 첫 성공 후보와 증인, 축·양끝 순서, 후보별 tick·확장 자원·점수·신경망 입력은 유지한다. 모양 검사 자체가 합법성이나 강제승의 증거는 아니다.

- 소스 SHA-256: `f83da1f387452c4f172b85ab51f7fc8f0be9cf26b47fc102a9613c144cc4e012`
- Reader SHA-256: `ebab87ee877c285c0896f41e9135491d0d73db5ef2ec001f14f8effeb2a49d65`
- 모델: 기존8119, SHA-256 `fce1c849e6eb05a1ec839550a2dc29ca509b0c7ce0d7ea6150095eeee1a91932`
- 캐시 식별자: `node-v14`. 검증에 사용한 HTML SHA-256은 `3ad5353d1888c718e47fa55e8399b4537166e06aa93b574b54b4384131f816e8`이다.

## 완료한 동등성 대조

15·19판의 회전·반사·색 교환과 경계·막힌 끝·끊어진 돌·긴 줄·3·3 모양을 포함한 생성 보드256개, 빈칸74,336개에서 독립적인 가상 중심 돌 검사와 모양 판정이 같았다. 실제 G 대조8짝에서는 후보 ID·순위 점수·첫 축/양끝/후속4목 증인·tick 노드 수가 같았고 보드·윈도·근처 돌 수·위협 인덱스를 복원했다.

작은 생성망과 기존8119에서 NN 누적 상태를 초기화한 뒤 임시 탐색과 실제 돌 배치·되돌리기를 검사했다. 양색32개 특징의 벡터80개가 새 보드 계산과 일치했다. 신경망 없음·생성망·8119의 잎과8119 부모를 비교한 원본 고정 작업8호출·4짝도 완료 점수·PV·노드 수가 정확히 같았다. 이 유한 대조가 모든 국면의 기력이나 제한 시간 결과의 동일성을 보장하지는 않는다.

## 원래 34돌 시간 조건

별도 예비 검사에서는 같은 프로세스에서 후보4와 후보5를 순서대로 기본 `createEngine(15, board)`·`analyze(1, 1500)`로 호출했다. 이후 필수 전체77 검사는 원문 순서·시간·단언을 유지한 채 한 번 실행했고, 실제 원래 대상 호출의 반환 뒤만 관찰했다. 대상 호출이나 앞부분을 추가로 재실행하지 않았다.

| 후보4 별도 예비 호출 | 1 | 24 | 39 | 통과 |

전체 흐름의 대상 호출은 실제 경과1,500.1374ms·CPU1,516ms였고, 해당 원래 Reader 검사 프로세스는 종료 코드0이었다. 선별·강제 검사 전체 완료 표시는 모두 false였다. 따라서 완료 깊이1·후보24개 비교를 확인한 결과이며, 모든 후보의 안전 검사나 필승·강제패배 증명 완료로 해석하지 않는다. 실행 순서·JIT·GC 등을 분리 측정하지 않았으므로 속도 향상 비율이나 실패 원인을 확정하지 않는다.

전체 기능 검사는 엔진77개, 브라우저368단계, NN 점수705개·특징 벡터1,410개·시간 종료 복원6개를 통과했다. 사용한 두 브라우저의 정상 종료도 확인했다. 이 기능 검사는 자동 최대15초의 실제 대국 평가를 대신하지 않는다.

## 예산·보존

기존 비용 원장87,797 CPU ms와 미사용2,203ms는 그대로 보존했다. 추가 진단의 측정 합계는9,094.125ms이고, 측정값으로 세지 않은 꼬리 비용 예약1,000ms를 합한 상한은10,094.125ms로 추가30,000ms 한도 안이다. 원래 전체 기능 검사에 포함된 대상 호출은 진단 원장에도 한 번만 기록하고 중첩 범위를 명시했다. 자식의 OS/자체 CPU와 감독 CPU를 중복 합산하지 않았다.

기존 모델·규칙·원본 자료·기보와 후보4의 세 실패 원본은 보존했다. 사용 중인 앱 v5.18.10의 SHA-256 `c89d82c623c8e7dd15b139d9379ce43fd84ab2d0c27093a445ba904c26ad6bf0`도 유지한다. 미채택 소스·검사·빌드·원본 실험은 로컬에 남긴다.

## 종료 기준 변경과 핵심8판

사용자는 **강제승·강제패가 확인되면 실제5목 전에 대국을 끝내도록** 종료 기준을 변경했다. 새 프로토콜 `final-proof-status-stop-v1`은 최종 엔진 상태·일관된 증명 표시·합법적인 추천/PV를 확인해 판정하고, 미확정 탐색 결과나 큰 점수만으로 종료하지 않는다. 전체 탐색의 시간 종료와 별도로 완성된 증명 상태는 구분한다. 이는 모든 상대 응수에 대한 추가 독립 수학 증명과도 구분한다.

이전 실제5목 종료 기준의 실행은 K5 12수·다른7판0수에서 저장·중단했고 완료 대국은0판이었다. 자식과 브라우저의 정상 종료를 확인했으며, 0수 중단판의 착수 로그가 없는 확인 단계에서 발생한 외부 도구 오류도 보존했다. 이를 승패나 추가 엔진 실패로 세지 않았다. 엔진·HTML·모델은 바꾸지 않았으므로 종료 프로토콜 변경을 후보6으로 세지 않는다.

일반 판정 정책23항목과 작은 생성 대국기록12항목이 실제 통과했다. 생성 검사 첫 실행은 A1을 기존 값으로 다시 쓰는 변조가 실제 보드를 바꾸지 못해 실패했으며 그 원본을 보존했다. V2는 그 변조 위치만 빈 O15로 바꿔 검증했다. 엔진이나 판정 기준을 낮춘 수정은 아니다.

새 기준으로 첫 수 K4·양쪽 자동 최대15초·동시 한 판의 핵심8판을 완료했다. **8판 모두 엔진 판정 종료이며 실제 정확한5목 종료는0판**이다. 새 실행의 기록·판정·종료 확인은 완료됐지만 기력 통과와는 구분한다.

## J6에서 남은 문제와 최종 판단

J6의 흑45수 K3는 완료된 깊이2·24후보 비교에서 선택됐고 점수는 `-9,999,994`였으나 상태는 미확정이었다. 미완료 깊이3은 버렸으며, 선택 PV에는 이미 다음 백 E8이 있었다. 따라서 현재 기록만으로 분석 중 후보가 새어나갔다거나 최초 상대 응수를 누락한 오류라고 단정하지 않는다.

백의 최종 엔진 자료에는 E8→H5→E6→D5→E5 수순과 전체 합법 응수178/178 완료 표시가 기록돼, E8을 실제로 두기 전에 백 강제승 판정으로 끝났다. **최초로 회피할 수 있었던 패배 분기는 아직 확인하지 못했다.** 45수 자체가 최초 패착이라는 증거도 없다.

핵심8판 전승 조건을 충족하지 못했으므로 추가16판과 앱 반영을 하지 않았다. 최종24판·기존22승 각각의 유지라는 목표도 달성하지 못했다. 현재 결과를 전체 기력 향상이나 선후공 필승으로 확대하지 않는다. 연구 문서와 일반 판정 도구·생성 검사는 유지보수 공개 범위로 분리하고, 미채택 후보5 엔진·관련 시험·빌드·모델·원본 대국은 로컬에 보존한다.
