# K5 공격 지속 보완 — 순차 연구 2단계

1단계 완료 명세를 검증한 뒤 K5 조사를 시작했다. 원인은 상대 첫 응수 누락이 아니라, **이미 생성한 방어·역공 겸용 후보가 얕은 탐색의 두 대표에서 빠지는 선택 경계**로 재현됐다. 이를 보완한 첫 통합 후보 v5.18.18을 로컬에 적용했다. 기존 실행 앱은 유지하며, 전체 기능 검사·3단계 CPU 비교·완전대국 합격을 구분한다.

## 입력과 실제 분기

기준은 이전 미채택 v5.18.17과 같은 8119 모델이다. 1단계 완료 시각 이후 실제 K5 원본 225수와 19~31수의 해시·보드·PV를 확인했다. 원본 기보 9,341,717바이트의 SHA-256은 `09c0a46678a63d4f85fa87fb0bf317a88f312d34a0961ec075d0fea95f97ac77`이다.

23수 H7의 완료 깊이 5 점수는 +9,999,993이었지만 `proven:false`였다. 별도 승리 검사는 완료했으나 증명을 만들지 못했고, 이를 강제승으로 표시하지 않은 것은 맞다. 저장 PV는 `H7→H8→H3→H4→M8→G3→M5`다. 독립 규칙에서 H7·M8은 즉시 사목이 아니며 H8·G3는 유일한 즉시 차단이 아니다. H3 뒤 H4는 유일 차단이고, 마지막 흑 M5는 M4·M9의 두 실제 승리점을 만든다. 마지막 형태가 성립한다는 사실만으로 앞선 상대 응수 전체를 증명할 수 없다.

실제 25수는 완료 깊이 4에서 M5와 H3를 모두 비교했다. M5 원점수는 −461.464036, H3는 −484.916452에 정책 보정 +1.76을 더한 −483.156452였다. 두 후보 모두 제외되지 않았고, M5의 PV에는 실제 상대 26수 M8이 이미 있었다. 분석 중 후보가 시간 종료로 그대로 반환됐다는 근거는 없다.

## 같은 지평과 후보 누락 재현

23수 분석 뒤 실제 H7·H8을 적용하면 남은 깊이는 3이다. 같은 생성 객체의 이 국면과 실제 25수 보드로 새로 만든 객체는 같은 원점수 +9,999,993을 냈다. 기존 잎별 5ms VCF 제한 대조군과 전체 호출 안에서 소검사를 마치는 대조군 모두 같았다. 후보 순서 교환·TT 비활성화도 깊이 3·4의 값을 재현했다. 새 부모 탐색의 동점 PV는 저장 PV와 일부 달랐으므로 PV 전체까지 동일하게 재현했다고 주장하지 않는다.

| 실제 H7·H8 뒤 후보 | 깊이 3 원점수 | 깊이 4 원점수 |
| --- | ---: | ---: |
| H3 | +9,999,995 | −484.916452 |
| M5 | +900.471176 | −461.464036 |

깊이 3의 mate 값은 새 루트의 ply 0 기준이다. 부모 좌표계의 두 수 거리를 반영하면 +9,999,993이며 실제 원점수는 변경하지 않고 별도 정규화 필드로 기록했다.

저장 수순에서 M8 뒤 백 차례의 같은 보드를 직접 비교했다. 깊이 0에서는 준비 후보 G3·M5·M4·L9를 만들었지만 공격 대표 G3와 차단 대표 M4만 남겼다. M5는 공격 192·차단 120을 가진 합법적인 겸용 후보였는데도 제외됐다. 깊이 1의 일반 탐색은 M5를 읽었다.

| 해당 백 국면 | 선택·후속 탐색 | 백 관점 원점수 |
| --- | --- | ---: |
| 기존 깊이 0 | G3 뒤 흑 M5의 지역 VCF | −9,999,993 |
| 기존 깊이 1 | M5를 포함한 일반 후보 비교 | +1,255.221820 |
| 겸용 대표만 추가한 대조군 | M5를 읽어 mate 영역 회피 | −379.129167 |

G3 뒤 흑 M5의 지역 VCF 자체는 실제 이중 승리점과 일치했다. 문제는 그전에 백의 다른 대응을 좁게 읽은 것이다. 점수 상한을 조절하거나 승리 증명 규칙을 느슨하게 바꾸지 않았다.

## 선택한 보완

첫 통합 후보는 다음의 작은 결합을 사용한다.

1. 기존 공격·차단 대표를 유지하고, 양쪽 특성이 충분한 중복 없는 겸용 대표를 하나 추가한다. 준비 후보는 최대 3개이며 준비 허용량 소진 뒤의 실제 사목 후보 최대 2개는 유지한다.
2. 여섯 번의 추가 **선택** 한도를 유지하되 합법적인 유일 차단은 그 선택 한도를 소비하지 않는다. 한도 0에서도 필수 차단만 해결하고 선택 분기는 멈춘다.
3. 실제 유일 차단을 수행한 뒤 각 색은 이미 쓴 준비 허용량을 자기 일회성 토큰으로 한 번만 복원한다. 공격자와 방어자를 같은 조건으로 처리한다. 토큰은 다시 생기지 않고 확장 한도도 증가하지 않는다.

실제 사목 후보를 최대 4개로 넓히는 대조군도 조사했으나 선택한 보완에는 포함하지 않았다. 사목 후보 풀과 일반 후보 생성은 기존대로 유지한다. 좌표 예외·돌 색별 성향·모델·규칙·신경망 입력·모드 상한·Worker 메시지는 바꾸지 않는다.

비공개 대조군의 혼합 모드 장치를 운영 코드에 복사하지 않았다. 실제 구현은 고정된 의미로 정상 검색 메모리를 지원하며, 전체 준비 마스크를 캐시 키로 구분한다. 의미가 바뀐 캐시는 `node-v12`로 분리했고, 공개 탐색 시작점 세 곳은 확장 6·준비/일회성 토큰 마스크 15로 시작한다.

## 비교 범위와 검증 상태

같은 후보·같은 완료 깊이의 비교에서 K5 H7은 기존 mate 값 대신 유한 값으로 바뀌고, K6 N6는 상대의 역공을 반영한 음수 값이 됐다. 후보 경계에서 놓친 위험을 더 읽은 근거이며 어느 후보의 승리나 전체 기력 향상의 증거는 아니다. 앞선 전체 보드 탐색의 4초 미완료는 단일 후보의 완료 시간과 직접 비교하지 않았다.

운영 구현과 비공개 대조군은 K5·K6의 잎과 단일 부모 후보 **4개 짝·8호출**에서 원점수·최종 점수·PV가 정확히 일치했다. 유한 진단은 58호출 중 54완료·4미완료, CPU 47.997초/90초이며 미완료 비교는 개선 근거로 쓰지 않았다. 입력 준비 CPU 0.282초는 별도 기록했다.

새 생성 회귀 검사는 대국 아카이브나 실제 모델에 의존하지 않는다. 모델 없음·작은 생성 MLP, 회전·반사·색 교환에서 겸용 후보 32건·준비 복원 32건·캐시 2건·규칙 16건·시간 종료 2건을 통과했다. 독립 규칙으로 540개 탐색 간선의 강제 차단·선택 예산·토큰 소비를 확인했다. 기존 관련 두 검사도 통과했다. 첫 시도는 공개 비교 루트의 마스크 15를 기존 관찰 계약이 다루지 못해 실패했으며, 실패 코드·로그를 보존하고 토큰을 지불한 복원을 독립적으로 검사하도록 보완했다. 기존 낮은 마스크의 일회 준비·단조성 검사와 모든 금수·5목·장목·캐시·복원 단언은 유지했다.

기존 PVS 및 회차 간 검색 메모리의 집중 검사도 통과했다. 전체 첫 실행은 기존 counterplay 관찰 계약이 필수 차단도 선택 예산으로 세면서 실패했다. 승인된 예산 계산식·후보 상한만 교정했고, 관련 4개 집중 검사를 다시 통과했다. 검사 삭제나 엔진 소스 변경으로 실패를 덮지 않았다.

다음 전체 실행은 통합 시나리오의 F7/H7 진단 정보 요구에서 실패했다. 해당 국면만 이전 분석 없이 실행하면 전체 강제패배 판정이 반환됐고, 기존 시나리오 전체를 단독으로 한 번 실행하면 F7/H7·D7/C7 진단이 있는 상태로 통과했다. 단독 시나리오의 입력·원본 단언은 그대로이며, 반환 후 정보만 별도 기록했다. 이 두 실행을 전체 실패가 해결됐다는 증거로 쓰지 않는다.

해당 단언은 최종 선택과 무관하게 특정 과거 후보의 진단을 요구하지만, 구현은 초기 Reader 상위 세 후보와 제한된 탐색에서 확인한 정보만 수집한다. 같은 단언이 과거 기준 엔진에서도 실패한 기록과 기존의 별도 CI advisory 분류가 있으나, 앞선 v16·v17의 실제 전체 회귀는 통과했다. 따라서 이번 실패를 자동으로 기존 실패나 부하 문제로 판정하지 않는다. 전체 문맥의 반환 후 관찰로 추가 확인하며, 원본 단언을 바꾸거나 advisory로 건너뛰지 않았다.

추가 단일 국면 재현 CPU 1.891초를 포함한 진단 누계는 49.888초였다. 원래 58호출 행렬의 47.997초와 별도로 계산하며, 단독 시나리오 및 전체 회귀 실행 시간은 기능 검사로 구분한다.

원본 단언을 유지하고 반환 후 관찰만 추가한 전체 실행은 통합 진단 국면에 도달하기 전에 다른 기존 검사에서 종료 코드 1로 끝났다. `game48.position(34)`의 1.5초 분석에서 완료 깊이가 1 미만이었다. 관찰 대상의 반환 기록은 생성되지 않았으므로 앞선 F7/H7 진단 부재를 설명하는 근거는 얻지 못했다. 실패 원본·관찰 설정·빈 기록과 실제 종료 상태를 보존했다.

그 국면의 별도 제한 대조에서 수정 후보와 보존된 v17 모두 24개 후보 비교 깊이 1을 완료하고 같은 수를 반환했다. 완료 시각은 각각 약 1.140초와 0.854초였고, 두 번 모두 전체 분석 상한은 약 1.501초였다. 이 단독 통과로 전체 실패를 해결됐다고 보지 않는다. 대조 CPU 3.938초를 더한 진단 누계는 53.826초/90초다.

확장 한도 0의 정적 반환을 후보 생성보다 앞당긴 비공개 대조도 실행했다. 즉시 승리·상대 위협·VCF 검사는 앞에 유지했다. K5·K6 한도 잎, 생성 필수 차단, 실제 부모 후보 두 곳의 **5개 완료 짝에서 점수와 PV가 같았고**, 관찰한 두 한도 잎의 버려지는 quiet 후보 생성은 각각 1회에서 0회가 됐다. 부모 후보의 시간은 일관되게 줄지 않았으며, 계측을 포함한 1.5초 국면은 양쪽 모두 깊이 0이었다. 따라서 이 최적화만으로 비교 지연이 해결됐거나 앱이 빨라졌다고 판정하지 않는다. 해당 대조 시점에는 운영 소스를 변경하지 않았다. 이 12호출 대조 CPU 8.624초를 더한 진단 누계는 62.450초/90초다.

검색 중 CPU 측정을 하지 않는 별도 단조 시계 대조에서는 기존·반환 이동 대조군이 첫 24개 비교를 각각 약 1.211초·1.085초에 완료했다. 반면 짧은 요청의 사전 검사 비율을 45%에서 25%로 줄인 대조군은 더 일찍 비교를 시작했지만, 22개만 끝내고 깊이 0으로 종료했다. 사전 검사를 줄이는 정책은 기각했다. 이 3호출 CPU 5.969초를 더한 진단 누계는 **68.419초/90초**이며, 단일 VM 대조의 시간을 브라우저 처리량 향상으로 확대하지 않는다.

이후 첫 후보의 소스·검사·공개 빌드 168개를 보존하고, 기존 반환문 한 줄 이동과 버전·엔진 식별자만 두 번째 로컬 후보 v5.18.19에 반영했다. 후보 폭 24·확장 6·토큰 15·원래 사전 검사 배분은 유지했다. 완료 값과 PV의 의미가 같으므로 캐시는 `node-v12`를 유지한다. 시간 내 완료 여부와 추천수는 달라질 수 있으며 전체 기능 검사와 대국 결과는 아직 미확정이다. 기존 실행 앱에는 배포하지 않았다.

두 번째 후보의 관련 집중 검사 6개는 모두 실제 종료 코드 0으로 통과했다. 생성 검사에 한도 소진 뒤 버리는 후보 생성 0·이전 위치의 반환문 변이와 점수/PV 일치 32건, 한도 0에서도 VCF 우선 유지 32건, 작은 NN과 같은 객체·공유 캐시 재사용 2건을 추가했다. 기존 겸용 후보·재충전·규칙·시간 종료·540개 간선 단언은 유지했다. 새 공개 빌드와 독립 파생본도 기존과 같은 4개 짝·8호출의 완료 값/PV가 일치했다. 이 새 동등성 비교 CPU 4.031초를 포함한 진단 누계는 **72.450초/90초**다.

두 번째 후보의 전체 실행도 같은 `game48.position(34)`의 1.5초 완료 깊이 단언에서 실제 종료 코드 1로 끝났다. 새 생산 동등성 비교는 통과했지만 전체 회귀는 통과하지 않았다. 통합 진단 국면·브라우저 368건·신경망 일치 검사에는 도달하지 못했다. 따라서 소스 후보 두 개 중 어느 것도 2단계 완료 조건을 충족했다고 보지 않으며, 3단계와 대국 검증은 시작하지 않는다. 추가 소스 후보 없이 원래 기보 검사 흐름 안의 구·신 엔진 시간 배분을 계측해 원인을 좁힌다.
