# v5.18.36 · 등록된 항성 증명의 조건부 전략 이어두기

백 선공 `H8 G7 F8 G8 G9 F10 H10 E7`의 실제 판에서 출발한다. 9수 I9 뒤 상대가 다르게 응수해도, 등록된 완전한 증명의 해당 가지를 찾아 다음 수를 이어 둔다. 기보 따라두기 체크 없이 자동 모드의 기본 추천과 반투명 선택지에 적용한다. 수 번호는 양쪽 착수를 합친 전체 수다.

적용 규칙은 `15x15-exact5-both33-v1`이다. 정확한 5목만 승리이며 양측 3·3을 금지하고, 정확한 5목 완성이 동시에 생기면 승리를 우선한다. 일반 렌주 자료의 평가를 그대로 필승으로 옮기지 않았다. 백·흑 선공과 회전·반사한 판을 따로 검증했다. 항성은 I3이며 한성 D1, 람월 I8과 구분한다.

## 이번에 연결한 221개 시작점

9수 I9 뒤 합법 상대 10수는 216곳이다. 그중 **215곳의 11수**는 실제 추천수 자체에 대해 현재 규칙의 완전한 승리 증명을 연결했다. 기존에 검증한 205곳과 이번에 확인한 10곳으로 구성한다. 다른 수가 이긴다는 증거를 해당 추천수의 증명으로 대신하지 않았다.

상대 10수 I11에 대해서는 기존 11수 G11 대신, **11수 J8 자체를 검증한 원자료 대안**을 사용한다. J8의 증명은 G11의 승패를 판정한 증거가 아니다. 상대 10수 H9 뒤의 11수 I11은 유지한다.

나머지 6개는 과거에 선택해 둔 완전한 증명을 저장 기보에서 계속 사용할 수 있도록 보존한 시작점이다. 해당 판과 실제로 둔 수가 맞을 때만 활성화한다.

| 상대 10수 분기 | 보존한 원증명의 시작 수 |
| --- | ---: |
| H9 | 15수 |
| J8 | 19수 |
| F11 | 15수 |
| H7 | 15수 |
| D7 | 27수 |
| F7 | 23수 |

따라서 등록 전략은 **215개 11수 시작점 + 과거 증명 6개 =221개**다. 각 시작점에는 다음 한 줄의 대표 PV뿐 아니라 필요한 상대 응수별 조건부 전략을 함께 저장한다. 저장 기보에서 이미 선택한 원증명이 확인되면 그 증명을 우선해 이어가며, 매 수 다른 승리 PV로 바꾸어 종국을 늦추지 않도록 한다. 되돌리기와 다시 두기에서도 실제 기보에 맞는 증명 시작점을 다시 확인한다.

상대 예측이 맞아 이전 일반 계산을 이어받는 경우에도, 실제 착수 뒤 현재 기보와 일치하는 등록 전략을 먼저 조회한다. 기본 추천과 반투명 선택지가 서로 다른 우선순위를 사용하지 않도록 같은 설정과 현재 판을 기준으로 처리한다.

## H7과 전체 9수 증명의 한계

**상대 10수 H7 뒤 기본 11수 I7은 여전히 미증명이다.** 반격을 찾지 못했거나 제한 비교를 완료했다는 사실만으로 필승·안전으로 표시하지 않는다. 이 사실이 I7 자체의 필패 증명이라는 뜻도 아니다.

H7 분기에는 `9 I9 → 10 H7 → 11 I7 → 12 F9 → 13 I6 → 14 I8 → 15 J8`로 도달한 15수의 완전한 증명이 별도로 있다. 그 15수 판부터 원전략을 이어갈 수 있다는 사실을, H7 뒤 모든 12수에 대해 11수 I7이 이긴다는 증명으로 확대하지 않는다. 따라서 **9수 I9 자체의 전체 필승은 아직 증명하지 않았다.**

이번 기능은 등록된 221개 원전략을 이어가는 기능이다. 자료가 없는 임의의 판에서 새로 얻는 모든 실시간 증명 DAG를 자동 등록·추적하는 기능까지 제공한다는 뜻은 아니다. 등록된 부모판이나 실제 착수가 달라지면 조회 범위를 벗어나 일반 분석이 필요할 수 있다. 유리한 21주형 지원과 불리·균형 5주형의 임시 제외 정책은 유지한다.

## 완료 비교·증명 수순·실제 증명 탐색의 구분

깊이와 노드는 다음 뜻으로 구분한다.

| 항목 | 의미 |
| --- | --- |
| 완료 비교 깊이 `depth` | 같은 깊이에서 후보 비교를 완료한 반복 깊이, 단위는 반수다. 증명만 얻고 후보 비교를 하지 않았다면 0일 수 있다. 방어 확장을 포함한 모든 내부 호출의 최대 스택 깊이라는 뜻은 아니다. |
| 표시 증명 수순 `proofPlies` | 화면에 보여주는 대표 증명 PV의 길이다. 전체 증명 DAG의 크기나 실제 검색 깊이가 아니다. |
| 증명 탐색 깊이 `proofSearchDepth` | 표시한 호출 범위의 진입판에서, 실제 방문한 탐색판에 추가된 돌 수의 최대값이다. 임시 합법성 검사만을 위한 돌 변경은 제외한다. 실패한 다른 가지가 최종 PV보다 깊을 수 있다. |
| 노드 `nodes` | 현재 분석·검사에서 실제 수행한 작업 카운터다. Reader의 방문·검사와 Forest의 재귀 호출 등을 세며, 서로 다른 판의 고유 개수라는 뜻은 아니다. |

Reader의 공개 증명 호출은 호출마다 실제 방문 깊이와 노드 차분을 측정한다. 고정 후보 검증은 그 후보를 둔 뒤의 검사 범위를 시작판 기준으로 바꿀 때 실제로 둔 한 수를 포함한다. 캐시에서 증명을 가져오면 대표 PV가 남아 있어도 새 방문 깊이가 0일 수 있다. 측정하지 않은 깊이는 미계측으로 두며 PV 길이로 채우지 않는다. 보조 `totalNodes`는 해당 Reader 내부 카운터 값으로, 다른 분석 호출에서 초기화될 수 있어 실행 전체의 평생 누적치로 해석하지 않는다.

즉시 승리나 후보 비교 전의 완전한 승리 증명은 완료 비교 깊이가 0이어도 유효하다. 반대로 깊이 0의 증명을 완료된 후보 비교로 표시하지 않는다. 과거 원자료의 depth·nodes·score·proof는 원래 증거로 보존하며 현재 실시간 측정값으로 승격하지 않는다.

등록 전략의 즉시 조회 결과도 실시간 검색과 구분한다. 조회 자체의 `depth`, `nodes`, `score`는 0이고 `proven`은false, `proof`는null이다. 화면에는 검증한 원전략을 이어 조회한다는 사실을 표시하며, 이번 호출에서 새 승리 증명을 찾았다고 표시하지 않는다.

## 짧은 사전분석을 자동 추천에 쓰는 기준

기존 네이티브 사전분석 가운데 **3초 완료 비교만 있고 완전한 승리 증명이 없는 7,955개**는 삭제하지 않고 보존한다. 자동 모드에서는 이 짧은 미증명 비교만으로 추천을 고정하지 않으며, 다른 유효한 등록 응답이 없는 현재 판은 선택한 설정으로 일반 분석한다. 7,955개 모두가 약하거나 불안전하다는 판정을 내린 것은 아니다.

별도 환원 사전분석의 **3초 미증명 비교 3,754개**에도 같은 자동 추천 기준을 적용한다. 네이티브와 환원자료를 합친 11,709개 원기록은 그대로 보존하며, 이 수치가 해당 수들의 기력·안전을 판정한 결과라는 뜻은 아니다. 같은 판에 다른 유효한 원자료·증명 전략·즉시 전술이 있으면 그 근거를 구분해 사용하고, 현재 조회가 없으면 새 분석이 필요하다는 뜻으로 처리한다.

별도로 **3초 자료 중 추천수 자체의 완전한 승리 증명이 있는 8,409개**는 일괄 제외하지 않는다. 자동 모드의 실제 배정 시간이 짧다는 이유만으로 이런 증명 자료를 차단하거나, 과거의 ‘3초 이상 설정에서만 적용’ 조건을 다시 넣지 않는다. 15초·25초의 완료 비교도 승리 증명과 구분해 사용한다.

이 8,409개는 네이티브 자료의 수치이며, 환원자료의 증명된 3초 항목 13개도 같은 허용 기준을 유지한다.

등록된 엔진 사전분석과 이번 조건부 전략은 심층 모드에서 현재 판을 새로 분석한다. 직접 설정의 실제 적용 요청 예산이 등록 증명의 원래 명시 예산보다 길면 조건부 전략 조회로 대신하지 않는다. 남은 대국 시계로 요청 예산이 줄어든 경우에는 그 적용 예산을 기준으로 삼는다. 원예산은 실행 경과 시간에서 추정하지 않고 원시 기록의 선언값으로 연결했다. 이번 221개 전략은 3초 128개,25초 93개이며, 이 값은 과거 예산 메타데이터다.

## 조회 범위와 용량

조건부 전략 형식의 고정 상한은 시작점 512개, 노드 65,536개, 상대 응수 연결 262,144개,8MiB다. 이번 데이터는 시작점 221개, 노드 1,142개, 상대 응수 연결 179,499개다. 이 별도 형식으로 원증명의 공통 가지를 공유하며 기존 S·C 행을 대량 복제하지 않는다.

정책 조회는 **이미 둔 수가 40수 미만일 때**, 명시된 내 수는 **39수까지**다. 마지막 정책 39수 뒤 상대 40수에 기존 즉시 승리 검사가 정확한 5목을 완성하면 **41수 종국**을 허용하는 별도 범위를 둔다.41수의 비전술 정책 조회를 허용한 것은 아니다. 보존한 D7의 27수 원증명에는 실제 41수까지 이어지는 합법 증거가 있어 이 구분을 직접 확인했다. ‘전체 종국 40수 이내’라고 표시하지 않는다.

기존 원자료 S는 **61,525개**, 네이티브 C는 **32,602개** 그대로다. 기존 행과 원시 증거를 삭제하거나 덮어쓰지 않았으며 S 상한 65,536개, C 상한 32,768개를 유지한다. 채택 모델도 유지한다.

## 독립 증명 검사 범위

정규화한 221개 전략을 백·흑 선공과 8방향 회전·반사에 대응시키면 **3,536건**이다. 최종 양색·D4 검사에서 **3,210건을 새로 재생**했고, 정확히 같은 증거를 확인한 **326건을 재사용**했다. 재사용은 별도로 독립 재생한 정규화 시작점 221건과, 이미 양색·D4를 검증한 7개 원증명의 중복 제외 105건이다. 원raw·증명·부모판·추천수·좌표 변환·규칙·모델의 연결을 확인해 다른 입력의 결과를 대신 쓰지 않았다.

독립 검사기는 원 추천수와 필요한 모든 합법 상대 응수를 현재 규칙으로 재생한다. 원증명과 압축 DAG의 조건부 전략이 같은지도 별도로 대조한다. D7의 39수 정책·40수 조회 거절·41수 정확 5목 종국은 양색·D4 16가지에서 확인했다.

이 수치는 원증명 재생 범위다. Worker 전달, 실제 기본 추천과 반투명 선택지, 클릭·이어두기·되돌리기, 분석 모드 전환 및 실행 HTML 검사는 증명 재생과 구분한다. 전체 역사 카탈로그나 모든 네이티브 방어 UI를 다시 실행한 것으로 확대하지 않는다. 이전 데이터 확장의 범위는 [v5.18.35 후속 기록](opening-hangseong-followups-20261109.md)에 남긴다.

## 검사에서 증명 기능과 실제 시간을 구분하는 기준

기존 준비 공격 검사에서 제한 시간 내 완전한 증명을 기대하던 일부 판은 이전 공개 엔진과 이번 엔진 모두 미완료로 끝났다. 원실패와 재실행 결과를 보존했으며, 제품의 증명 단계 예산을 늘리거나 미증명을 승리로 바꾸지 않았다.

CI의 준비 공격·역공 증명 기능 검사는 단조 증가하는 작업 시계와 사례별 작업 상한을 사용한다. 양색·D4, 실제 선택수, 준비 공격의 성립, 필요한 모든 합법 상대 응수와 독립 증명 재생은 그대로 검사한다. 이 결과는 실제 15초 안의 완전승 보장이 아니다. `OMOK_STRICT_WALL_PROOFS=1`은 해당 검사의 원래 실제 시간 기준을 실행하며, 별도 `npm run test:proof-wall-smoke`는 실제 자동 15초의 추천을 승리 증명 또는 미완료로 구분해 검사한다. 기존 제한시간 실패를 전체 통과로 바꾸어 보고하지 않는다.
